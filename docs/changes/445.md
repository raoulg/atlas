A Python annotation written through two modules, `torch.nn.Module` after `import torch`, took `torch.nn.Module` and
also `torch.nn`, the module it is written through, so the overview drew `nn` as a type in the `▾ torch` frame beside
`nn.Module` (vectormesh's trainer writes it this way). Now the annotation takes the one type it names, however it is
spelled: `Module`, `nn.Module` and `torch.nn.Module` read alike, as Rust's `model::Order` and `crate::model::Order` and
TypeScript's `model.Order` of `import * as model` already did. The pair `qualified` holds it in the three languages: the
side that imports each type by its name and the side that writes it through its module have the same nodes, edges, flow
and findings (`a_type_written_through_its_module_is_that_type_in_every_language`).

Kind: drawn wrong, now right.
