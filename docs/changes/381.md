A route that writes `data/raw/{kind}/download.json`, or makes `data/raw/{kind}/parts/`, and a route that lists
`data/raw/` drew two places with nothing between them, although what the first writes is what the second reads: a
listing of a folder reads everything made below it. Atlas now orders the places on the disk by their terms: a place
lies in every folder above it and in every pattern that holds it (`data/out.csv` in `data/*.csv`), and the flow says,
for each place, the places of the program it lies in (`lies_in`). Each place keeps its own term; the order is a
quotient of them, as a directory is of its files. The picture draws a place in the outermost place of the program it
lies in, whatever the crowd of files: `File(data/raw/) · 2` is one box that the downloads write and the listing reads,
and opening it shows `data/raw/` and what lies in it, in its frame. It holds in Python, Rust and TypeScript alike (the pair `meets`),
and where the code takes the folder from a value Atlas does not follow, nothing it writes lies in what it lists: the
code does not say they are one folder.
