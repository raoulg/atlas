A lookup the language's library writes as a call (`levels.first()?`, `levels.get(0)?` and `map.get(name)?` in Rust,
`levels.at(0)` and a `Map`'s `levels.get(name)` in TypeScript, `next(iter(levels))`, `d.get(k)` and `d.get(k, default)`
in Python) was a step of its own that gave the part it picked, so a route that took an element this way drew one box
more than the same route written with a subscript (`&levels[0]`, `levels[0]`, `d[k]`). It is now the projection the
subscript is: no step, the part glued into the step that takes it, handed the collection it comes from; a default
(`d.get(k, quiet)`) is the other part it may hand. What the call is written of is read where its value is, a name bound
to it stands for the collection, a list changed in place first holds the value the change gave (#355), and a change of
the part it picks is the change of the part a subscript picks (`row = next(iter(rows)); row.append(level)` changes the
`rows` the function is handed, as `row = rows[0]` does; where a reader does not yet read that as a change of the
collection is #374). Which calls are lookups, and on which collections, is a table per language (`knowledge::Lookup`);
a method of the program's own type by the same name is still the program's. In Rust a tuple a tuple pattern takes
apart binds each name as a `let` of its element would, as Python's `a, b = x, y` already did: `let (first, second) =
(&levels[0], &levels[1])` hands `levels` on where it handed nothing.
