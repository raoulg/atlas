`[project.scripts] ask = "ask:main"` names the function `main` of the module Python imports as `ask`. Where that
module is a file of its own beside the package (a flat layout's `ask.py`, a src layout's `src/ask.py`), Atlas did not
find it, and drew the file as a script run by its path: `$ python ask.py`, whose top level runs nothing, so the route
reached no place. Now the declaration is read as Python reads it, in every layout: the command `$ ask` starts at
`main`, and its route draws what the program does, the address between `main`, which sends to it, and `hear`, which
reads the greeting back, and the screen it prints to. The file a declaration names is entered through it, and is no
script of its own besides; where it also runs as a program it is entered as a package's module is, by `python -m`.

A file a `bin` names, or one run as `__main__`, stays the program's start: its top level is its route, and its call
of `main` is a step of it.

```text
example: engine/tests/pairs/sockets/python/clean, route _root.ask.main (before: _root.ask)
  0.71.0 (985d0733)   Script ask.py: $ python ask.py → ask; no place
  with #364           CLI ask: $ ask → main → Web(127.0.0.1:7878) → hear, main → Screen
analyze --no-cache, Atlas and every program under engine/tests/pairs, base against branch: only the sockets pair's
Python client moves, both sides: `_root.ask` loses its script entry `ask.py`, `_root.ask.main` is the CLI `ask`.
The programs under engine/tests/plans and the Python fixtures read as before. The places pair has a third layout,
`beside`, the command in `cli.py` beside the package, drawn as the flat and the package forms are.
```
