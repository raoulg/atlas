A name bound to what the language computes of names with no call (`let gap = first.db - QUIET.db`, `let both =
[first, &QUIET]`, `const both: Level[] = [first, QUIET]`) was read two ways. Python followed it to the names it is made
of. Rust and TypeScript kept it as a value of the body's own: a step handed `gap` took nothing, a step handed `both` took
the body's `Level · both` in place of the two levels, and the module's quiet level never reached either step. An
operator is no step, and binding its result to a name adds no arrow, so in all three languages a step handed such a name
is now handed what the expression written in its place hands: `draw(gap)` takes `first` and `QUIET`, as `draw(first.db -
QUIET.db)` does. The name is still the body's own (`binds`). A choice (`a if c else b`, `x ?? y`) and a part a call makes
(`samples.abs() > 0`) are read as before. Where the body computes the name, its own arrow still reads the operands
(`Level · QUIET → named`); that part is open.

```text
example: engine/tests/pairs/locals/rust/shortcut, route signal.named
  0.71.0 (9cce2767)   Level · both → list, nothing → draw, Level · QUIET → named
  with #328           Level · first ×2 → draw, list; Level · QUIET ×2 → draw, list; Level · QUIET → named
analyze, Atlas and every program under engine/tests/pairs (311 programs): in the pairs only the locals pair's Rust and
TypeScript sides move (the steps of `named` are handed the levels, `return both` reads them, `both` holds no type of its
own); in Atlas's own Rust code 12 functions move, each where a `let` binds a comparison, a cast, an arithmetic, a tuple
or an array of names (`let in_module = n.kind == NodeKind::Module` now hands `n` where `in_module` is handed or read)
```
