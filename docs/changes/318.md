A name a function binds to an expression no step makes, `loud = samples.abs() > 0`, `let both: [Level; 2] = [first,
second]`, `const both: Level[] = [first, second]`, was taken for a module's name: the step that called the function drew
it as a value from beyond, `Tensor · loud → _loud`, beside the samples it is really made of. The graph now says the body
binds such a name itself (`binds`), as it said of a literal, in Python, Rust and TypeScript alike: a local is the body's
own value and nothing comes from beyond. A module's constant the body reads (`samples == FLOOR`) still comes from beyond,
by its name.

```text
example: engine/tests/plans/leaf-binds-a-local, route marks.peaks
  0.70.0 (eeca2256)   Tensor · loud → _loud, Tensor · samples → _loud
  with #318           Tensor → _loud
analyze, Atlas and every program under engine/tests/pairs: only `binds` grows (266 names in 37 subjects), nothing else moves
```
