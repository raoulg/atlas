A part's reading is kept with what its reader asked of the repository: each question it put to the listing (is
`Cargo.lock` there, which `.rs` files lie under `src`, which folders in `src` hold an `__init__.py`) with its answer,
each file it read with its bytes, and what it took from its environment. The reading is kept while the answers and
the bytes stay the same, in all three languages alike.

Before, adding any file under a part made Atlas read the part again, even a file no reader opens: `git pull` bringing
in `docs/x.svg` re-read all of Atlas. Now such a file leaves the kept reading in use. `atlas-code serve` asks the same
of the page it shows. A picture, a note or a log added to the working tree leaves the page as it is. A file of code
where a reader lists it is drawn. So is a change to `.atlasignore`, which the server used not to see on its own.

Nothing in the picture changes: `atlas-code analyze --no-cache` writes the same graph for Atlas and for every program
under `engine/tests/pairs`. What changes is when Atlas reads.

Bars: Warm view of Atlas after adding docs/x.svg, before = 18.4 s; Warm view of Atlas after adding docs/x.svg, after = 1.0 s; serve redraw after adding docs/x.svg, before = 29.2 s; serve redraw after adding docs/x.svg, after = 0.0 s | `atlas-code view . --no-open` of Atlas right after a warm run and adding one file no reader asks about (`docs/x.svg`), and the time `atlas-code serve` spends drawing again after the same change (after: none, the page stays); 0.70.0 (`edca626`) and `next` at `8ec396d`, built and measured interleaved on `perf.yml`'s runner, the median of five rounds each ([run 41210347169](https://github.com/raoulg/atlas/actions/runs/41210347169)).
