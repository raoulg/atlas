A decorator written as a call (`@strict(least=1)`, `@jaxtyped(typechecker=beartype)`) was drawn as a step of the module
it stands in, with the library's own places at the route's border, and one written as a name (`@guarded`) was not drawn
at all. Both are now part of the definition: no step, and a mark `guarded` on the function they are written above, which
names the decorator. A call of that function hands on what the decorator may end with, so the error a check raises
stands where the check runs: `tidy guarded +1 error`. Wrapping a function by hand (`tidy = guarded(_tidy)`) is still a step, and
Atlas does not follow the calls of such a name.
