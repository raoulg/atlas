A function that opens a file or a connection and hands it to another left that other function with no place.
`count(f)` read nothing and `emit(out, n)` wrote nothing, so Atlas asked of `emit` why it does nothing. A Node client
that connected with `net.createConnection(7878, "127.0.0.1")` reached no network at all, and a Python socket made by
`socket.socket()` and then bound had no address. Now every operation through a door (a `read`, a `write`, a
`sendall`, a listener for `"data"`) is a line of its own to the place the door was opened at. That holds wherever the
door is handed, in Python, Rust and TypeScript. An address is `host:port` however the code writes it:
`("127.0.0.1", 7878)`, `SocketAddr::from(([127, 0, 0, 1], 7878))`, or a port and a host handed apart. So a client and
a server meet at one Network place. Rust's `File::options()` is read as `OpenOptions::new()`.

```text
example: engine/tests/pairs/sockets/typescript/clean, route greeter.ask.main
  0.71.0 (9cce2767)   createConnection → conn → hear → Screen; no network
  with #323           main and hear → Web(127.0.0.1:7878)
example: engine/tests/pairs/handles/python/clean, route tally.main
  0.71.0 (9cce2767)   main → File(report.txt); count reads nothing, emit is asked why it does nothing
  with #323           File(data.txt) → count, emit → File(report.txt)
analyze, Atlas and every program under engine/tests/pairs: only the doors' traffic moves (Atlas's server reads and
  replies at 127.0.0.1:{port}; the file objects of seven Python pairs; the sockets and handles pairs)
```
