A call on a value the code declares of a class, with an override below it, is a step that may run one of several
functions. In the built pair (`engine/tests/pairs/built/python`), `report(section: Section, ..)` calls
`section.show(heading)`: a `Section` runs the `show` it inherits from `Block`, a `Boxed` below it its own. The step now
reads as `docs/reference/mathematics.md` ("Method resolution order") says: the function the call reaches is named by
the class it runs on, and the count takes in every function the call may run, the one it reaches among them unless an
interface, a protocol, a trait or an abstract class only declares it.

```text
route notes.report.report, the call section.show(heading)
  before   ▸ Block.show · one of 1
  after    ▸ Section.show · one of 2          opened: Section.show · one of 2, with Boxed.show inside
```

The same count moves wherever the reached method has a body of its own: `draw_all` in `what-holds` calls `draw` on a
declared `Shape` and may run `Shape.draw`, `Circle.draw` or `Square.draw`, one of three. A call through a class
(`Section.show(s, h)`) or through `super()` still names the method by its own class, and a call on a value built at the
call (`Section().show(heading)`) runs one function and is no choice.
