Whether a read is used is one rule, the same in Python, TypeScript and Rust: what a read gives is used where it
reaches what the step hands on (returned, handed to a call, kept), and it is a check where it only decides a choice,
goes to an error or is dropped.

- **A name nothing reads drops the value.** `f(x)`, Python's `_ = f(x)`, `done = f(x)` with `done` never read,
  TypeScript's `void f(x)` and Rust's `let _ = f(x)` are drawn alike: what was handed to `f` on the way is used. A name
  that is read only in a condition still makes the read a check.
- **A `match` is followed into what its arms bind.** In Rust, `match conn.read(&mut sink) { Ok(0) | Err(_) => break,
  Ok(_) => {} }` only decides, so the read is a check, as Python's `if not conn.recv(1024): break` and Node's
  `conn.on("data", () => {})` are. A `match` whose arm binds a name that goes on, or whose own value goes on (the
  tail of a function), uses the read. A Rust function's last expression without its `;` is its value, a `match`
  or `if` among them.

The clean `linger` of the sockets pair is now a check in all three languages.

No picture: the difference is the side of a place in a route that both reads and writes there, and the pairs' routes
agree in the three languages.

Kind: drawn wrong, now right.
