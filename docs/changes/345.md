A folder walked by two functions that call each other in turn (`mirror` lists a folder and hands each entry to
`mirror_entry`, which hands a folder back to `mirror`) was followed one round at a time, down to a limit: one place per
level, and at the limit a folder no call hands. Atlas now treats the functions that call each other as one recursion
and follows it to where it ends, as it already did for a function that calls itself (#325). What `mirror` reads is
every file in any folder at any depth in `photos/`, and what it writes goes into any folder at any depth in `archive/`.
The same holds in Python, Rust and TypeScript (the pair `trees`).

```text
example: engine/tests/pairs/trees/python/clean, route backup.main
  next (06afdeda)     mirror_entry reads photos/*/, photos/*/*/, … one place per level; writes {source}/*/…/*
  with #345           mirror_entry reads photos/**/*; writes archive/{name}/**
the gate (every program under engine/tests/pairs and plans): only trees moves, 19 → 10, 22 → 8 and 50 → 18 touches
  in Python, Rust and TypeScript
on Atlas itself: Libraries.follow and follow_in call each other; Environment.real now completes where Libraries.entry
  hands it its path
```
