`atlas changes` lists a node by the dotted name a reader finds it by, from its part's root (`Block.scaled`,
`cli.Repo.fetch`). A sum written in place in a signature (`x: Float[Tensor, "batch {self.size}"] | Tensor`) has no
such name. It is one object wherever it is written, and its id is the set of its variants' ids. `changes` listed it
by that id, `ext:` tags and all. It now lists it by the name the view draws it by: its own name, as the code writes
it, with its module where another type shares that name (`model::said`). No `ext:` tag reaches the report.

No picture: the page already drew the sum by its name. What shows the change is the output of `changes` on the program
of `engine/tests/one_name.rs`, a block whose method `masked` takes that union, to which the second commit adds a
method that takes the same union:

```text
changes HEAD~1..HEAD, on no route
  0.71.0 (f239e878)     ~ (ext:jaxtyping.Float[Tensor, batch {self.size}] | ext:torch.Tensor): was Float[Tensor, "batch {self.size}"] | Tensor: taken by masked · one of Float[Tensor, batch {self.size}], Tensor
  with #369 and #370    ~ Float[Tensor, "batch {self.size}"] | Tensor: was Float[Tensor, "batch {self.size}"] | Tensor: taken by Block.masked · one of Float[Tensor, batch {self.size}], Tensor
```

The same sum turns up in a real subject, vectormesh, a component that takes `BaseComponent | nn.Module`:

```text
changes db24a7e~40..db24a7e, on no route
  0.71.0 (f239e878)     + (ext:torch.nn.Module | vectormesh.types.BaseComponent)
  with #369 and #370    + BaseComponent | nn.Module
```

The reading itself is unchanged: `atlas analyze --no-cache` gives the same graph, byte for byte, with both builds on
`engine/tests/fixture`, `fixture-ts`, `fixture-rs` and `fixture-parts`. What moves in `changes` over Atlas's own history
is #370's.
