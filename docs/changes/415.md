---
issue: 415
title: The loading bar no longer shows 99 % while most of a reading is still to come
area: cli
pictures: [415-bar.png]
---
Before, a start was taken to be quick when the index of its build of Atlas held anything, and the bar expected
what the last quick start took. When the index no longer held for the working tree, the start read all the code
(82 s on a Python program of 45k lines) while the bar expected a second, and stood at 99 % almost the whole
time; the next start that did find its index was then held to those 82 s and opened at 1 %. Now a start reads
code once it reads a part its index does not hold, which the server knows within moments, and only then shows a
bar, timed by the last starts that read code. The time expected fills four fifths of the bar; the last fifth is
for a reading that takes longer and moves in seconds, so a wrong estimate shows as a slow last fifth, never as a
bar at 99 %. A start that finds its index opens the page without a bar.
