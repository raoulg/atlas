The empty path names nothing, so an input whose default is the empty path is named by the input alone. A program that
writes its report to `process.env.REPORT ?? ""` and its log to `process.env.LOG ?? ""` was drawn writing both into one
place, named by nothing, and the two steps were folded into one pill (`saveReport, saveLog ×2`). Now each writes the
file its variable names, `Disk({$REPORT})` and `Disk({$LOG})`, as the program that asks for each variable is drawn; so
also `os.environ.get("REPORT", "")` in Python and `env::var("REPORT").unwrap_or_default()` in Rust. A file whose path
names no place keeps no literal of the call that touches it as its name: `open(os.environ["CARD"])` reads
`Disk({$CARD})`, not a file called `CARD`, and `path.with_suffix(".count")` of an untyped path no file `.count`; a
format the call says stays (`json.dump` writes `*.json`).
