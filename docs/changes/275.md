Nothing a user sees changes: inside the engine a language is now one of the three Atlas reads (`Lang`), and a
repository's graph holds the set of its parts' languages, where a single name used to stand for one language and an
empty one for both no parts and several. The JSON keeps its shape: each part names its language, and the graph names
one when all its parts share it and none otherwise.

What shows it is `atlas analyze` with the build before and after, cold (`--no-cache`, a fresh cache directory), on
Atlas itself and on every program under `engine/tests/pairs`, among them `requests`, whose parts are read in Python,
Rust and TypeScript:

```
subjects=292 identical=292 differ=0 failed=0
```

Atlas's own graph (12,871,694 bytes) is the same file byte for byte with either build, and so is each of the 291
programs. The law it rests on is `the_merged_languages_are_the_union_of_the_parts` in `engine/tests/merge.rs`: the
languages of a merge are the union of its parts', in two steps as at once, and they come back from the JSON.
