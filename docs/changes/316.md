A nightly Studio, and `atlas-code` from the nightly, asked GitHub which commit the newest nightly is by the release's
target, which stays at the commit the release was first made at. Every nightly then saw that old commit as newer:
**Update and restart** installed the build that already ran, and the offer came back. They now ask the tag `nightly`,
which moves to each build once its files are up, and Studio asks again after an update instead of keeping the answer
the build before it got. Nothing in the picture changes; what GitHub said:

```text
release nightly, its target:   edce364   (what was asked: "↑ nightly edce364")
tag nightly:                   f5bb2b2   (what is asked now: the build that runs, so no update)
```

A build from before this still sees edce364; its update installs a build with this, and then the offer is gone.
