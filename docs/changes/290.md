`atlas-code serve`, and Atlas Studio with it, used to read a program twice on a cold start: first without its libraries,
to show a preliminary picture, then again with them, sharing nothing. Now it reads once, at the libraries asked for.
The loading page shows one bar, and the page opens on the complete picture, the one an agent's `atlas-code mcp` reads
as well. After a change in the code, the page keeps its last complete picture ("the code changed · drawing…") until
the next one is drawn, instead of swapping in an incomplete one. The reasons are on #290 (label `decision`).

Bars: Cold start to the first picture, before = 10.8 s; Cold start to the first picture, after = 19.8 s; Cold start to the complete picture, before = 29.8 s; Cold start to the complete picture, after = 19.9 s | `atlas-code serve --no-open` of Atlas itself, empty cache (`XDG_CACHE_HOME`) and no `.atlas/index`, from the start until `/api/drawn` first names a drawing, and until it names the complete one (before: the second drawing; after: the first and only, so its two bars are one moment); 0.70.0 (`edca626`) and `next` at `8ec396d`, built and measured interleaved on `perf.yml`'s runner, the median of five rounds each ([run 41210347169](https://github.com/raoulg/atlas/actions/runs/41210347169)).
