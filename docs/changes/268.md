issue: 268
title: "A value built at the call runs its own class's method; one a parameter declares may run any override below"
area: engine
commit: (this landing)
pictures: []
---
A method called on a value now runs what the classes the value may be run. Where the code builds the value at the call
(`Block().show(heading)` in Python, `new Block().show(heading)` in TypeScript), its class is the one it builds, and the
step runs that class's method alone: an override in a subclass is no longer drawn as one of the methods it may run, and
the call no longer hands on the errors that override raises. Where a parameter declares the class (`section: Section`)
and the method is one `Section` inherits, the value may be a `Section` or any class below it: the step is now a
choice between the method `Section` runs and each override below it (`Block.show`, `Boxed.show`), and the call hands on
what each may raise. Rust is read as before: a struct has no type below it, and a `&dyn Trait` was already a choice
between the trait's implementations. In the built pair (`engine/tests/pairs/built/python`), the error `Boxed.show`
raises follows the call that may run it:

```text
atlas analyze engine/tests/pairs/built/python/clean -o clean.json
jq -c '.nodes[] | select(.id == "notes.report.report") | .sites[] | select(.to == "notes.sections.Block.show") | .fails // []' clean.json
  before   []
  after    ["ext:builtins.ValueError"]

atlas analyze engine/tests/pairs/built/python/shortcut -o shortcut.json
jq -c '.nodes[] | select(.id == "notes.report.note") | .sites[] | select(.to == "notes.sections.Block.show") | .fails // []' shortcut.json
  before   ["ext:builtins.ValueError"]
  after    []
```
