issue: 259
title: Notes and looks are kept whole when the page and an agent write at once
area: cli               # also mcp
commit: 15016f3b
pictures: []
---
The page of `atlas serve` and an agent through `atlas mcp` share the notes, the look and what is shown as files in
`.atlas/`. When both wrote at once, a note could be lost or two notes could get one number, and a look the agent sent
while the page took the last one could vanish unread. Now every change to these files holds a lock that both processes
respect, and every write goes through a file of its own. A notes file that does not read is no longer taken for no
notes, after which the next note replaced it: it is said, and left as it is. A note's number beyond 2³² is refused
instead of naming another note, and a commit given to `resolve` is shortened by its characters, so one with an accent
no longer stops the log from telling what happens to the notes. Nothing in the picture changes. The answers show it:

```text
.atlas/notes.json that does not read, then a note written on the page
  before   the page shows no notes; the file is replaced by the new note alone
  after    atlas  could not read the notes: .atlas/notes.json does not read as Atlas writes it; it is left as it is, to mend or remove: …
           the note is refused (500) and the file is unchanged

resolve {"id": 4294967297}, with note 1 open
  before   Note 1 on count is resolved
  after    `resolve` takes a note's `id`, a number from `notes`, and the `commit` and `issue`, if any.   (note 1 stays open)

resolve {"id": 1, "commit": "ééééééééé"}
  before   the log stops: its thread panics, and no note is said again
  after    agent  resolved note 1 on count (in ééééééé)
```
