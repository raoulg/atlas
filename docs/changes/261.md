A fault inside ty, Python's type checker, on one file ended `atlas view`, `serve` and `check` for every language, and
one notebook whose JSON did not parse failed the whole repository. Now the file ty fails on is read without its types
and the rest is read as usual; a script or notebook that does not load is left out. Each says so on the terminal:

```text
ty failed on /path/to/project/src/pkg/odd.py, which is read without its types: <ty's message>
skipped notebooks/broken.ipynb: parsing notebooks/broken.ipynb: <the notebook's error>
```

A panic inside one MCP tool answers that call with an error, and `atlas mcp` answers the next message. A panic while
`atlas serve` draws is logged, the page shows the drawing as failed with what the panic said, and the watch goes on to
the next change. A request whose handler panics is answered 500.
