Each language now says in one place where the code of a library lies, starting from the file that imports it: Rust
looks in the crate's own manifest and the workspace's lock, TypeScript in `node_modules`, Python in the environment's
search places. Two cases come out of that.

A Cargo workspace whose members depend on two versions of one crate showed one library, the version of the member
read first, and both members' calls went to it. Now each member reads the version its lock pins, and the picture shows
two libraries, `notekit-0_1_0` and `notekit-0_2_0`, as it already did for crates with separate locks (#378). The same
holds for Python (two uv path dependencies) and TypeScript (two `file:` dependencies).

Two parts that share a library but call different parts of it drew one function of it two ways. A part that called
only `save` saw it touch the disk itself; a part that also called `write` saw `save` call `write`. The merge kept
whichever part came first. Now every part reads the shared library over what all of them call, so `save` calls `write`
in both parts and in the merge, in either order (#377).
