Shift-clicking a package to focus on it drew it with a border of its own: a package that takes and makes tensors of
four ranks showed one type crossing from the rest of the code and nothing going out, where the overview drew the
tensors on both sides. A type could also stand inside a package in one focus and outside it in another, as the
focus decided where it stood from its own packages alone.

The focus is now the part of the overview's plan that touches the packages in focus, with the rest of the code
around it, and the picture is drawn from it the way the overview is drawn from its plan. A package in focus drawn
closed has the border it has in the overview. A type stands where the overview puts it, in every focus and at every
zoom. The rest of the code is one block, drawn on the left with what it gives the focus and on the right with what
it takes. Opened, each of its packages stands on both sides. A type that only the rest makes and only the focus
takes is drawn as one arrow from the rest to the package, counting the types it carries (`1 type`).

Kind: drawn wrong, now right.
