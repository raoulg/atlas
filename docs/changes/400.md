The overview drew all the code, tests included: a package that keeps its tests beside it read the test's fixture file
and made the test's own types, and on Atlas itself the three parts drew the fixture files of the test code beside the
files the program reads. It now draws the program alone: no test, no code a reader marks as test code (Rust's
`#[test]`, `#[cfg(test)]` and `tests/`, pytest's `test_*.py` and `conftest.py`, a `*.test.ts` and what lies below
`__tests__`), no code in a test module, and no place only a test hands a path to. The chip `without test code ✕` above
the picture says so and lets go of it; `+ without test code` takes it again. The link and an agent's view carry it as
`tests: true`.

What moved. In the shelf, `store` holds `disk` and its pytest file `test_disk`: without the test code `store` reads
`shelf.csv` alone, and `File(fixtures/shelf.csv)`, which only the test hands `load`, is gone with `test_disk`. A package
of tests alone (a crate's `tests/`, a folder `__tests__`) is not drawn. Taking the test code away first and grouping what
is left is not the same as grouping first: `store` stays a box, with fewer lines. The before pictures are the overview
with the test code, as 0.71 drew it.
