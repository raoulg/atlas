title: A path's parent is a path's only where ty says so, and so is Path(..)
area: engine
commit: ec6504b8
pictures: []
---
Atlas read `x.parent` and `x.parents[n]` as the directory above `x`, and any call to a name `Path`, `PurePath`,
`PosixPath` (and the other pathlib classes) as a path made of its parts, whatever `x` or `Path` was. They now hold only
where ty finds the attribute or the class in pathlib: a dataclass of your own with a field `parent` is read as that
field, a class of your own named `Path` as your own class, and where ty cannot say what a value is (a parameter
without an annotation), the directory stays a hole named by the code rather than a guess. `p.name`, `p.stem`,
`p.suffix` and the like are read as any attribute is. The receivers pair (`engine/tests/pairs/receivers/python`)
shows it: the same program, with and without its annotations.

```text
the files they open             clean (annotated)            shortcut (unannotated)
shelved(entry: Entry), reads
  before                        {entry}/../{name}            {entry}/../{name}
  after                         {parent}/{name}              {parent}/{name}      (the entry's own fields)
log(source: Path, ..), writes
  before                        {source}/../shelf.log        {source}/../shelf.log
  after                         {source}/../shelf.log        {parent}/shelf.log   (a hole: ty does not know `source`)
```
