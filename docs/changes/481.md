title: "`topology` closes a folder as a reader does, so the gate before a promotion holds the law again"
area: release
commit: (this landing)
pictures: []

Nothing a user sees changes: opening a folder of places and closing it gave back the picture it was all along. The gate
before a promotion, `uv run tools/pictures.py topology`, closed an opened folder only by its chip in the bar, and since the
bar lists what is opened on request (behind "1 box ▸") it found no chip and reported every folder it opened as one that
does not close. It now closes a box as a reader does: by the title of the frame it opened into, and a folder whose files
only spread out by its chip, with the list opened first. What shows is the gate's output on a program that reads seven
files from each folder below one directory (`engine/tests/plans/folds-two-levels`):

```text
before  folded.run · opens folder w:File:data/*/
            does not close to the picture it was
        2 boxes opened in 1 of 1 routes, 1 that do not refine the picture they open from, 0 that draw a line more than the closed box did
after   2 boxes opened in 1 of 1 routes, 0 that do not refine the picture they open from, 0 that draw a line more than the closed box did
```
