Atlas followed a path into the functions that build it within one bound on how deep the whole expression nests, the
helpers' bodies counted in. So the same place was found when the code wrote it in one expression and cut off when the
code named each folder with a function of its own: the archive's stand-up notes were written to
`{monthDir.folder}/11/2/meetings/standup.md`, the name of a folder three helpers down left as a hole. Now each function's
return is read once, as a term of its parameters, and every call writes what it hands into that term: the notes are
written to `~/archive/2026/11/2/meetings/standup.md`. The bound counts one function's own expression; a value a field, a
parameter's default or a constant holds is read in the frame it is written in, alike. So in Python, Rust and TypeScript.

None of the pairs under `engine/tests/pairs` reads otherwise (`atlas-code analyze --no-cache`, 356 programs, the same
graphs). Atlas itself reads two places further: the manifest its TypeScript libraries' reader reads is
`{a}/node_modules/{spec}/package.json` where it was `{d}/package.json` (beside it Cargo's and ty's roots, since a field
is read as every constructor of its type sets it: #407), and what `Environment::real` is handed names the file below the
root (`{root}/{p}`) where it named the root. The callers that make that path whole are followed to a fixed count, which
the extra alternative uses up sooner: 22 of them, tests that read a pair, are no longer drawn (#406).

Bars: Reading Atlas, cold, before (c99bf1d) = 9.8 s; Reading Atlas, cold, after = 9.2 s | `atlas-code --no-cache analyze`
of Atlas at this commit on a laptop (Apple M-series), the mean of the second and third of three runs each, one after the
other: each function's returns are read once, never once per call.
