A unit struct's name is a value of it, built where it is named. Outside a macro the Rust reader already drew it that
way: `Plain.show(&heading)` builds a `Plain` and runs `show` on it. Inside a macro's arguments it did not:
`println!("{}:", Plain.name())` ran `Plain.name` on a `Plain` that no step made. Now the macro's form reads the same as
the other one: a `Plain()` step builds the value, and `name` runs on it. The same holds for a unit struct handed as an
argument inside a macro (`vec![Box::new(Rust), ..]` builds a `Rust`). In the shortcut of the built pair
(`engine/tests/pairs/built/rust/shortcut`, route `notes.report`), the `Plain` before `Plain.name` had no maker; now
`Plain()` makes it, as it already made the one before `Plain.show`:

```text
route notes.report, the steps
  before   unwrap_or_default, Plain.name, Plain(), Block.show on Plain
  after    unwrap_or_default, Plain(), Plain.name, Plain(), Block.show on Plain
```

Python and TypeScript already build a value inside an f-string or a template (`f"{Plain().name()}"`,
`` `${new Plain().name()}` ``).
