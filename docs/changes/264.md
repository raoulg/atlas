Atlas read `x.home()` as the user's home and `x.joinpath(..)`, `x.with_suffix(..)`, `x.with_name(..)` as a path's,
whatever `x` was, and `os.getenv`, `os.environ` and `os.path.join` by their names. They now hold only where ty finds
the call goes into pathlib, importlib or os: a class of your own with a `home()` method is followed into its own body,
and where ty cannot say what a value is (a function without a return annotation), the place stays a hole named by the
code rather than a guess. The receivers pair (`engine/tests/pairs/receivers/python`) shows it: the same program, with
and without `def data_dir() -> Path`.

```text
shelf.summary.summarise, the files it reads and writes
                 clean (annotated)                     shortcut (unannotated)
  before   ~/data/{name}, ~/data/{name}.count     ~/data/{name}, ~/data/{name}.count
  after    ~/data/{name}, ~/data/{name}.count     summarise.source, .count  (holes: ty does not know `data_dir()`)
```

In a notebook, only what ruff parses as an IPython escape command (`%matplotlib inline`, `!pip install ..`,
`files = !ls`) is set aside. A line Black wraps before an operator (`    % len(rows)`, `    != other`) is Python, and
the files it opens are read as they are in a script.

A package's `exports` is read as Node reads it, for a library in `node_modules` and for your own package alike: its
conditions in the order the package writes them, the first an import of code meets taken, `types` never. A package
that writes `require` before `import` is read at its `require` build.
