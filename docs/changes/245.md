A file the code names only by a name of the function that writes it is that function's place, as a parameter's value
already was (`analyze.dir`): two functions that each write a `file` Atlas cannot follow drew one `Disk(file)` and now
draw `Disk(save_report.file)` and `Disk(save_log.file)`; closed, the two stand in `into disk` until it is split. A value
a function binds is named by the binding with the function's name (`{main.folder}/note.json`), and a method's
parameter by its class and its own (`Repo.read.dir`). What `expect(..)` or `context(..)` is handed is a message, never
the name of a place: `path.parent().expect("has a parent")` is the folder, not the text. Atlas drawn by itself no
longer has the `Disk(file)`, `Disk(path)` and `Disk(dir)` that each stood for many files.
