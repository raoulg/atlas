A step that sets an object up counts for a method called on that object later in the route. The page already read
it so (#309). The engine's read-back, which finds what a function reads back and changes, read only the chain of
callers above a step, so the two answered one question in two ways. Both now read one order: a call ran before another
when it stands before it and no choice holds them in different arms, and in a loop every call of the loop ran before
every call of it.

On the `setup` pair the page draws what it drew. Two shapes now draw as the code runs them:

- **A loop.** The report is kept on the shelf that a later call in the loop opens again. `write` writes the report in
  both folders. It wrote only in the drafts' folder before.
- **A nested arm.** The report is kept in an `if` inside the arm that set the shelf up. It is written in `out`. It was
  the disk at a path no code decided.

The engine's arrows are the same on Atlas itself and on the subjects above, so `analyze` and the MCP say what they
said.
