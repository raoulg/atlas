What a parameter of no type of the code's holds and which errors a call hands on are now worked out from the calls the
route draws. A call through a class (`Section.show(section, heading)` in Python,
`Section.prototype.show.call(section, heading)` in TypeScript) runs that method and no override of it; the route already
drew it so, but an override's parameter still counted as filled by such a call, so the override's body read a value no
call of the program hands it. Building a class whose initializer is a base's, a `super()` call and a call on a value of
a known class now fill the parameters and hand on the errors of the method each runs along the class's order, as the
route draws them. No route of the pairs draws differently; the graph does. In the through pair
(`engine/tests/pairs/through/python/shortcut`), `Boxed.show` is run by no call, and no longer reads `heading`:

```text
atlas analyze engine/tests/pairs/through/python/shortcut -o graph.json
jq -c '.nodes[] | select(.id == "notes.sections.Boxed.show") | .uses // []' graph.json
  before   [{"name":"heading"},{"name":"heading","arms":[[0,1]]}]
  after    []
```
