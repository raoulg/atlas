What `atlas changes` says a changed type was names the types at its arrows by the names the view draws them by. A
shaped array keeps its shape, a dot in it too: `Float[Tensor, ... {self.size}]`, where `changes` said `size}]`, the
part of its id after the last dot, and said two shaped arrays of one tail as one. A sum is named as the code writes
it. `changes` names a node through the function the view's names come from, `model::name_of`: the name its reader
gave it.

No picture: what shows it is the output of `changes`, on the program of `engine/tests/one_name.rs`, a block whose rows
are `Rows = Float[Tensor, "batch {self.size}"] | Float[Tensor, "... {self.size}"]`, to which the second commit adds a
method that takes and gives `Rows`:

```text
changes HEAD~1..HEAD, on no route
  0.71.0 (985d0733)   ~ Rows: was Rows: taken by scaled · given by scaled · one of size}]
  with #358           ~ Rows: was Rows: taken by scaled · given by scaled · one of Float[Tensor, ... {self.size}], Float[Tensor, batch {self.size}]
```

The release builds of the base (985d0733) and of this change agree everywhere else:

| command | subjects | before and after |
| --- | --- | --- |
| `atlas analyze --no-cache` | a copy of Atlas at 985d0733 and the 343 programs under `engine/tests/pairs` | identical |
| `atlas changes --no-cache`, text, `985d0733~1`, `~10`, `~60` and `~150` against `985d0733` | Atlas | identical, 263 MB |
| `atlas changes --no-cache`, text, `HEAD~40..HEAD` | vectormesh | identical |

No type's words in those ranges name a type whose name holds a dot past a bracket, so none of their lines moves.
