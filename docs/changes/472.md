A TypeScript package is read as its compiler reads it: the files `tsconfig.json` (or `jsconfig.json`) names by `files`
and `include` (everything, `**/*`, when it names neither), less what `exclude` and `outDir` leave out, along `extends`
and `references`, and every file one of those imports. A script beside `src/` that the config does not exclude, such
as `scripts/summarize.ts` run with `tsx`, is now read: where `package.json` names the command that runs it, it is that
command's route (`summarize`); else it is entered by its path, as a Python script beside its package is. A file the
manifest runs and a test the runner finds are read whatever the config says; without a config, the code under `src/`
is read, as before.

What was found and not read is said, in one line, with the folders: `atlas-code view` and `atlas-code analyze` end with
`2 files not read: functions/ 1, scripts/ 1`. On the pair, a script run by hand and kept out of the tsconfig:

```
before  digest · digest · 3 modules · 0 entries
after   digest · digest · 3 modules · 0 entries · 2 files not read: functions/ 1, scripts/ 1
```

and the same script declared (`"summarize": "tsx scripts/summarize.ts"`, the tsconfig's default `include`):

```
before  digest · digest · 3 modules · 0 entries
after   digest · digest · 5 modules · 1 entries · 1 file not read: functions/ 1
```
