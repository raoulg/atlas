A name bound to what the language computes of names (`let gap = first.db - QUIET.db`, `both = [first, QUIET]`, `` const
key = `${day.station}` ``) stands for those names: a step handed `gap` takes `first` and `QUIET`. The route's own arrow
still read them where the name was bound, so a route that only hands `gap` to `draw` drew a line of its own from
`QUIET`, which the same route with `first.db - QUIET.db` written in `draw`'s call does not draw. Binding a value to a
name adds no arrow, so the route now reads those names where it reads the name, as it reads the root of a projection
bound to a name: where only steps are handed the name, only those steps take the names, and `named` draws as `written`
does, in all three languages. Where the body's own code reads the name (`print(gap)`, `return both`), it reads the
names there. A name a step makes anew is a value of its own and is read as before.

```text
example: engine/tests/pairs/locals/rust/shortcut, route signal.named
  0.71.0 (f312fb20)   Level · first → named, Level · QUIET → named; Level · first ×2, Level · QUIET ×2 → draw, list
  with #343           Level · first → named; Level · first ×2, Level · QUIET ×2 → draw, list
analyze --no-cache, Atlas and every program under engine/tests/pairs (319 programs), base against branch: 9 move, and
each only loses a read of its own code at a binding. The locals pair's `named`, both sides in all three languages, no
longer reads the levels itself. `ReadingStore.summary` in the Python shortcut of `pairs/python` and in the lens pair's
TypeScript shortcut no longer reads `day` where it formats the query or the key it hands to its steps. In Atlas's own
code 7 functions lose a read where a binding's value is an array, a vector or a tuple of names, or a cast or an
arithmetic of one (`let mut stack = vec![start]` hands `start` to the steps that pop and push it; `let i = at as usize
- 1` reads `at` where `lines[i]` is read), and 5 only read their names in another order.
```
