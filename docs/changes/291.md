What a Rust program reads from or writes to one of std's sockets (`TcpStream`, `TcpListener`, `UdpSocket`) reaches the
web, as what Python's `socket` receives and sends does. A server that reads a client's name and writes its greeting
drew no place at all, and `atlas check` asked whether its `answer` and `linger` were dead; both now go to the web.
Connecting, reading, writing, sending and receiving move data; binding an address, accepting a connection, shutting a
half and setting a timeout move none, in either language. A read through a dereference, `(&*conn).read(..)`, is a read
of `conn`.

The shortcut that lingers by sleeping (`thread::sleep`) instead of shutting its half and reading what the client still
sends reaches no place, and Atlas asks what the wait leaves behind. The web the server talks to has no address in the
picture (`?`): the address is bound in `main`, and a connection a listener accepts is handed on without it.
