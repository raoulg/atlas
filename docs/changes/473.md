A path whose folder an object holds is completed from two callers: the one that set the object up, and the one that
hands the rest. Atlas paired every set-up with every caller of the rest. So the folder a command sets its ledger up on
was joined with the stamp that only a test hands, to a ledger of its own, and `check` named a file that nothing writes
as a place the command decides. A completion now stands only where one route meets all the callers it needs, so a
literal a caller hands is a place of the routes through that caller and of no other. The routes drew these files
nowhere before either; what changes is the graph and `check`. The same holds in Python, Rust and TypeScript (the pair
`engine/tests/pairs/apart`).

`atlas-code check engine/tests/pairs/apart/python/clean`, before:

```
ledger/cli.py:9  Pipeline() decides itself where data lives: data/blocked/blocked_latest.jsonl and data/blocked/blocked_20260823.jsonl
    write_text(data/blocked/blocked_latest.jsonl) in Ledger.flush
    write_text(data/blocked/blocked_20260823.jsonl) in Ledger.flush
```

after:

```
ledger/cli.py:9  Pipeline() decides itself where data lives: data/blocked/blocked_latest.jsonl
    write_text(data/blocked/blocked_latest.jsonl) in Ledger.flush
```
