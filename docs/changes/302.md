A Rust server that binds its address in `main` and hands each connection it accepts to a function drew the web it
talks to as `Web`, with no address: the function that reads and writes the connection does not name it. A connection
is a door to the place it was opened at, and keeps that place wherever it is handed, as a path does. The greeter's
`answer` and `linger` now reach `Web(127.0.0.1:7878)`, the address its listener is bound to, and a client that
connects there and hands the connection to `hear` reaches the same place: the two ends of a connection meet at one
box. It holds however the connections are taken (`incoming()`, `accept()` in a `let` or a `match`, a clone), and a
socket's address names its place as a URL's host does. Where the code does not say the address (only the environment
holds it, or Atlas cannot evaluate how it is built), the place stays unnamed.

Python's sockets move data by the same operations as Rust's: a client's `create_connection`, and `sendmsg`,
`recvmsg`, `recvfrom_into`, `sendfile` and `connect_ex`, now reach the web as `TcpStream::connect` and its reads and
writes do. A crate whose own path runs through a module named `net` is judged by its own row, not as a socket.
