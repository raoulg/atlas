A closed step draws no line from a file it reads back: what it wrote and then read is internal to it. What a function
reads back is worked out in each context it can be called in, and a set-up the function runs itself counted as one of
them, as if a caller above it had run it first. So a write that ran before the set-up was read as landing in the
set-up's folder too, and a file the function only reads was taken as one it reads back: its closed box drew no line
from the file, and the file was missing from the picture until the box was opened. A function's arrow now stands in the
contexts it is called in: the route that starts at it, and each chain of calls that leads to it, with what ran before
it there. A set-up it runs itself counts for what follows it in its body, never for what came before.

In the shortcut of the new `order` pair, `review` keeps its report in `out`, then sets the drafts up and reads the
report from them. Nothing in the route writes `drafts/report.txt`. The closed `review` now reads it from the left;
before, the file was absent, and opening `review` drew a line the closed box did not. The clean side reads its report
back before it sets the drafts up, and draws as it did.

A function also no longer stands under a caller that never calls it: in the cooperative pair, `lines` and `Cached.read`
change the store as they name it, `self.root / key`, and `{cache}/{url}` is changed where a `Feed` builds that store.
