Atlas reads a Rust program a third faster on a cold start: `atlas-code view`, `serve`, `mcp` and Studio, wherever no
kept reading is there to reuse. Reading itself at `--libraries 1` took 28.5 s on `perf.yml`'s runner and now takes
19.1 s. Almost all of the reading is spent linking bodies, not parsing them. A body's reader asked tree-sitter for
the parent of a node again and again, and tree-sitter finds it by searching down from the top of the file each time.
It also walked the same body once for each kind of node it looked for. Now each function is walked once, and the
parents and walks are answered from that walk. The picture stays the same: `atlas-code analyze --no-cache` writes the
same bytes for Atlas itself (at `--libraries` 0, 1 and 2), for every program under `engine/tests/pairs` and for every
fixture.

`atlas-code view --timings FILE` also says where a reading's time went, stage by stage (parse, items, reach,
signatures, the bodies, callers, globals, finish, fiber, index), per part and per crate or package
(`docs/reference/performance.md`). `perf.yml` has a `compare` mode that measures two commits with those stages, also
on commits of Atlas that both builds read, so that a slower reader is told apart from a larger program.

Bars: Atlas reading itself, cold, before = 28.5 s; Atlas reading itself, cold, after = 19.1 s | `atlas-code --libraries 1 view` of Atlas at `4ef2ca0`, an empty cache and no `.atlas/index`; before: `b370a39` (`next` at `4ef2ca0` with the stages of `--timings`), after: `a1d8fe1`, built and measured interleaved on `perf.yml`'s runner, the median of five rounds each ([run 41220997980](https://github.com/raoulg/atlas/actions/runs/41220997980)).
