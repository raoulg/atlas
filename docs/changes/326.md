Whether a touched file's path is fixed by the code (`fixed`, the path starts at a literal) is decided by the same table
of path functions each reader evaluates paths with, and no longer by a second list of constructor names. A path
function says which of its arguments the path starts at: the first for a join, a parent or the path as it is, the base
for a URL resolved against one (`new URL("./x.json", import.meta.url)` starts where the module does, not at its
literal), none for a place of its own (the home, the temp directory, the environment). Nothing a user sees moves on the
pairs or on Atlas itself: `atlas-code analyze` of every program under `engine/tests/pairs` and of Atlas gives the same
graph with and without this change, apart from what #248 and #327 change.

```text

  with #326           data/{name} fixed · src/x.json · data/{name} fixed
```
