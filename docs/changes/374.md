When code changes a part it picked by a subscript or a lookup, the whole collection changes. Examples: `rows[0].push(level)`,
`let row = &mut rows[0]; row.push(level)` and `rows.first_mut()?.push(level)` in Rust; `rows[0]!.push(level)` and
`rows.at(0)!.push(level)` in TypeScript; `row = rows[0]; row.append(level)` and `next(iter(rows))` in Python.

Atlas now draws each of these as a step handed the collection. The step gives the collection anew, and the next step
takes the new value. Before, Rust's step went missing and the rows went straight to the next step. TypeScript's step
was a call Atlas could not follow, and it gave nothing.

To find the part, Rust and TypeScript now read the element type that a written collection type gives (`rows:
&mut [Vec<Level>]`, `rows: Level[][]`). Failing that, they read the elements of the literal the collection was built
from (`vec![vec![first]]`, `[[first]]`). In Rust, a `let` bound to a `&mut` part borrows it, so a change through the
`let` changes the collection. The index that picks the part is only read: `fills[k].push(..)` changes `fills`, never `k`.

When the collection belongs to the module (`ROWS[0].push(level)`, or a `let` bound to a part of `ROWS`), the change
writes the module's value `Global(signal.ROWS)`, in every language. In Rust, the lookups twins `added` and
`added_looked_up` now draw as one route.

```text
example: engine/tests/pairs/lookups/rust/clean, route signal.added
  0.71.0 (d08df1b0)   Level · rows → show
  with #374           Level · rows → push → Level · rows → show
analyze --no-cache, Atlas and every program under engine/tests/pairs (350 subjects), base against branch: 8 move.
The lookups pair, in all three languages and on both sides. Rust's `added` gains the `push` that changes `rows`, which
its twin `added_looked_up` already drew; on the shortcut both twins gain it, after the step that takes the module's rows;
`grown` and `grown_looked_up` gain it on both sides. TypeScript's `added` and `addedLookedUp` turn `row.push`, which
gave nothing, into a `push` that gives `rows`; their `grown` twins gain it, so `show` is handed `rows` where it was
handed `first`. Python's and TypeScript's `grown` (and `pushed`) hand the collection to the change where they handed its
first element. On the shortcut, Python's and TypeScript's `added` twins read and write `Global(signal.ROWS)`. In
TypeScript's clean ledger, `expenseFrom` reads `category.trim()` as a step handed `fields`, as it already reads
`DATE.test(date)` two lines up: `category` is now typed `unknown`, the element type of `ReadonlyMap<string, unknown>`.
In Atlas's own code, `body::Steps::fills` gains the two `push` steps that change `fills` and `through`, and
`parts::versions` gains the `insert` that changes `out`. Every other move in Atlas is a byte offset in the reader that
changed. Atlas's findings: one more reviewed, for `holds_container` and the five functions beside it in the TypeScript
reader.
```
