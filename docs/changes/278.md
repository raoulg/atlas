Nothing a user sees changes. Inside the engine an id is one of the code's or a name past the fiber the graph keeps of a
library, and the tag that tells them apart is reached through one prism, `model::ext` (`of`, `path`, `is`, `name`),
spelled once; where a reader resolves a name, it gets that choice as a value, `Resolved::Code` or `Resolved::Beyond`.
The JSON still writes `ext:plotkit.data.load`, so the page and its plans read what they read.

No picture: what shows it is the output, the same bytes from a release build of the base (f312fb20) and of this change,
each run with `--no-cache` on a `git archive` copy of Atlas and on every program under `engine/tests/pairs`:

| command | subjects | before and after |
| --- | --- | --- |
| `atlas analyze` | 342 | identical; Atlas's own graph 14,325,292 bytes, 285 names past the code in all |
| `atlas --libraries 0 analyze` | 342 | identical; Atlas's own graph 13,486,900 bytes, 292 names past the code in all |
| `atlas view --no-open` | 342 | identical, apart from the build's version line |
| `atlas changes`, text and `--json`, `f312fb20~5..f312fb20` and `f312fb20~60..f312fb20` | Atlas | identical, 0.85 GB of output |

The laws it rests on: the prism's (`path(of(p)) = Some(p)`, `of(path(id)) = id` where it has a path, an id of the
code's has none) and a resolved name read back from its id, both proptests in `model.rs`; and
`a_name_past_the_code_goes_through_one_prism` in `engine/tests/readers.rs`, which holds that no reader, and nothing on
the graph side, writes the tag, tests for it or takes it off by hand.
