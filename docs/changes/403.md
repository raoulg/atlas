Every test a runner collects is now a route of its own, in Python, Rust and TypeScript alike: a pytest `test_*`
function (or a `test_*` method of a `Test*` class), a Cargo `#[test]` function, and each callback a `*.test.ts` hands
`it` or `test`, labelled by its string (`kiest kort`). A Python test appeared in no route menu before; a TypeScript test
file was one route for all its tests, and is now the module that holds them, as `test_cli.py` is.

The tests beside the package are read too (#404): a Python project's `tests/` (`tests/test_cli.py` is the module
`tests.test_cli`, the name pytest gives it), and a `tests/` or `test/` beside a TypeScript package's `src/`, as a crate's
`tests/` was. Their test code is left out of the overview by default and kept with one click, as all test code is.

What a test is, and what is test code, is one table per runner (`knowledge::TestConventions`: pytest, Cargo, Vitest and
Jest), read by one function for every language. Nothing shows a picture of it on its own: the pair
`engine/tests/pairs/tests` shows that a shelf with one test reads alike in the three languages, the program the same,
the test code the same, the test by the same label, and that a test kept inside the package cuts its module in two
where one kept beside it cuts none.
