Atlas reads each function body once for the questions it asks of it: where each node stands, which statements come
before it, and where each name is written again. A cold `atlas view`, `atlas check` or Studio start of a large program
is about 2.7 times as quick; on Atlas itself the reading went from about 45 s to about 16 s of processor time. Nothing
in the picture changes: `atlas analyze` writes the same graph, byte for byte, for Atlas and for each of the 430
programs under `engine/tests/pairs` it reads.

A cold `atlas view` of Atlas (157 modules, `--libraries 1`), release builds of `0607e9f7` before and after, three runs
each, alternated, on an 18-core Apple M5 Pro shared with other builds (load 10 to 21); median, with the range:

```text
                      before                  after
user time      45.0 s (43.6–45.3)     16.9 s (16.5–17.5)     −63 %
wall time      54.6 s (50.5–59.5)     19.6 s (17.6–25.4)
read phase     48.8 s (47.2–56.0)     16.0 s (13.5–16.6)     (`--timings`)
flow phase      3.4 s  (3.2–5.7)       4.1 s  (3.0–9.2)      (unchanged code; load)
peak memory    809 MB                 808 MB                 (set by `flow::of`, #289)
```

Cold is a fresh `XDG_CACHE_HOME` and the worktree's `.atlas/index` removed, as #270 measured.
