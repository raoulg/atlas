Inside the engine, where a path, URL or statement becomes whole through its callers is a record with four named
fields: where it is whole, the term it is there, the function that decides it, and the function that set up the object
whose field holds its root. The last two are both function names, and as places in a tuple they could be swapped
without anything noticing. Nothing a user sees changes: `atlas analyze` writes the same graph, byte for byte, built
before and after, for every program under `engine/tests/pairs` and for Atlas itself.

```text
atlas-code analyze, built from f33f41c3 and from 79c6e20b
  276 programs under engine/tests/pairs   identical
  Atlas at f33f41c3                       identical   327720c8…
  Atlas at 79c6e20b                       identical   b0b76061…
```

Atlas's own picture gains one box: `paths::Completion`, a type with the fields `whole`, `term`, `decided_in` and
`set_up_in`, which `Callers.at` and `Callers.of` return. Before, they returned a tuple Atlas drew no box for.
