`atlas-code changes` (and the MCP tool `changes`) printed a change once for every route it is on: a new step inside a
method that ten commands pass through stood ten times, and a place whose arrows differ listed every function that
touched it before, a hundred callers of `print` among them. Now the changes on the same routes stand together, once,
under those routes, the first three by name and the rest counted; a changed place says the arrows it gained and lost,
a test's marked, counted when there are many. The JSON still holds every route, and each changed place gains its
`lost` and `gained` arrows. What `changes` finds is the same. Five commands and two tests through one method, with a
step put into it and a test added:

```text
before                                                     after
~ CLI · five                                               ~ CLI · five
    + step clean.Cleaner._prepare                          ~ CLI · four
    ~ step clean.Cleaner: was Cleaner: built by …          ~ CLI · one
    ~ place Screen: was five prints · four prints ·          and 4 more routes
      one prints · test_one prints · test_two prints ·         + step clean.Cleaner._prepare
      three prints · two prints                                ~ step clean.Cleaner: was Cleaner: built by …
    ~ composition clean.Cleaner.clean:                         ~ place Screen: + test_three prints (test)
      clean.Cleaner._strip ⇒                                   ~ composition clean.Cleaner.clean:
      clean.Cleaner._prepare → clean.Cleaner._strip              clean.Cleaner._strip ⇒
                                                                 clean.Cleaner._prepare → clean.Cleaner._strip
… the same four lines again under CLI · four, CLI · one,
CLI · three, CLI · two, Test · test_one, Test · test_two   + Test · test_three
                                                               + place prints <c>
+ Test · test_three
    + place prints <c>
```

On Atlas's own last fifteen commits the report went from 3924 lines to 467.
