A function that a package exports is a door: its users run it with whatever they hand it. A path it builds from its
parameters is then a place its users decide, as well as the places the program's own callers hand it. Rust and
TypeScript drew both. Python drew only the second, because it marked its doors after it had worked out who makes
each path whole. Python now marks them first. `keep(text, home)`, exported from the defaults pair's package, draws
`work/.made/kept.txt`, where the command keeps its note. It also draws `{home}/.made/kept.txt`, the workbench of the
home a user hands it. The set is the same in all three languages.

A command that a framework registers (`@click.command()`, `@app.get(…)`, a tool server's `@tool`) and that its
package also exports is now both the command and a door. Before, the command lost its door. A declared program
that its package exports was already both.

Two laws hold this:

- `an_exported_function_keeps_its_users_places_in_every_language` (`pairs.rs`), in the defaults pair, for three
  languages and both sides.
- `an_exported_command_is_the_command_and_a_door` (`pairs_python.rs`).

Kind: drawn wrong, now right.

## For the implementer

Both laws are marked `#[ignore = "#435: red until it lands"]`. Remove the mark once a law passes.

**Red today:**

```
python clean: `keep` keeps one place more, the users' home, a value no code decides: {("work/.made/kept.txt", false)}
```

Rust and TypeScript give `{("work/.made/kept.txt", false), ("{home}/.made/kept.txt", true)}` on both sides. The flag
says whether a conjunction of `Touch::by` holds `Atom::Starts`. `an_exported_command_is_the_command_and_a_door` fails
on `greet.exported`: base reads `Cli greet [--out]`, `exported=false`.

**The cause is the order, as the issue says.** The trace:

- **Where completion reads the doors.** It reads them in one place, `paths::complete` (`engine/src/paths.rs:1876`),
  through an `entry` closure that each reader hands it. An entry is also completed by its users (`Whole::users`,
  `paths.rs:1598`). The closure is `n.entry.is_some()` in every reader: Python at `python/passes.rs:588`, TypeScript
  at `typescript/passes.rs:1083`, Rust at `rust/passes.rs:588-590`.
- **Rust marks its doors before `link`.** `pub` items are marked in `collect_symbols` (`rust/passes.rs:154`, `:243`),
  and `mark_exports` runs at `rust.rs:212`, before `link` at `rust.rs:221`.
- **TypeScript marks its doors before `link`.** `mark_exports` runs at `typescript.rs:249`, before `link` at
  `typescript.rs:251`.
- **Python marks its doors after `link`.** `link` runs at `python.rs:442`, and completion runs inside it
  (`python/passes.rs:591`, `place_calls` at `:593`). `mark_exports` comes later, at `python.rs:445`.
- **One function marks every Python door.** That function is `python/passes.rs:998`. It covers `__all__` over the
  names `__init__.py` imports (the defaults pair), `from … import *` with the module's `__all__` (the doors pair),
  and a root or single module without `__all__` (sockets, handles, places/flat). So one law over one form holds them
  all. The doors pair draws no place, so a law on its places would compare empty sets. The defaults law is the law
  of the issue.
- **Moving one line fixes it.** Spike 1 moves `mark_exports` above `link`, and the defaults law passes.
- **Plugin entry points come late too.** Python's plugin entry points are doors as well (`Export` named
  `group:name`, `entries.rs:121-123`). They are marked by `entries::mark_scripts`, which runs only after the reader,
  at `language.rs:113`. Completion does not see them either. No law holds them yet: `tests/fixture` declares
  `fixture.exporters` on a class.

**The rule belongs in `builder.rs`.** The readers do not share a pipeline: each reader's `parse` orders its own passes.
They do share two things. `GraphBuilder::export` (`builder.rs:230`) is where every reader marks a door. `paths::place_calls`
(`paths.rs:1949`) is where every reader writes completion, once. Put the rule in those two places, so that it holds by
construction:

1. **One function decides an entry's kind.** Write `GraphBuilder::enter(id, Entry)`; the order the marks come in must
   not matter. `Export` yields to every other kind and sets `n.exported = true`. That rule is already written, in
   `mark_scripts` (`entries.rs:127-133`). Any other kind stays when `Export` comes after it. `export`, `mark_scripts`
   and Python's `mark_registered` all go through `enter`. `mark_registered` filters on `n.entry.is_none()` at
   `python/passes.rs:837` and writes at `:876-880`.
2. **A late door fails.** `place_calls` records in the builder that the doors have been read. `enter` then refuses an
   `Export` with `debug_assert!`, so a door marked after completion fails every debug test of its reader. Tests
   (`entries::mark_tests`, after completion in all three languages) are no door, so the guard leaves them alone.
3. **In `python.rs`, mark first.**
   - Call `mark_exports` above `link`, after `star_imports` and the bindings (`python.rs:435-437`).
   - Call `mark_scripts` there as well, in place of `language.rs:113`. It reads `store.imported` and `store.bindings`,
     which `python.rs:364` and `:437` have set by then.
   - With step 2 in place, moving only one of the two fails at once.

**The traps.** Spike 1, which moves `mark_exports` alone, has three:

- **A registered command loses its kind.** A command, route or tool that its package exports is `Export` before
  `mark_registered` looks at it. `mark_registered` skips it (`python/passes.rs:837`), and `export` never overwrites
  (`builder.rs:231`). So the command is drawn as a door, without its options. `an_exported_command_is_the_command_and_a_door`
  shows this: under spike 1 it reads `Export greet []`. Step 1 is the fix.
- **Flat scripts gain their users' places.** Spike 1 moves five laws in `pairs_python`:
  - `sockets_a_connection_keeps_its_place`
  - `nothing_a_socket_is_a_place`
  - `doors_a_sockets_operation_goes_its_way_in_every_language`
  - `doors_a_sockets_linger_only_checks_in_every_language`
  - `handles_a_file_handed_on_keeps_its_place`

  Python's `greeter.answer`, `greeter.linger`, `tally.count` and `tally.emit` gain the touches their users make:
  `answer` reads twice and writes twice where Rust's does once, and `count` reads at `""`. Python names a flat
  module's public functions as its doors. That is the reader's rule (`Leaves { exports: true }`, `language.rs:125`),
  and the places pair (`flat` exports its `main`) and the sloppy pipeline (its four doors are asked) hold it. The
  Rust sides are binaries, whose `fn answer` is no door. So the code changes, not the rule: give `greeter.py` and
  `tally.py`, both sides of each, `__all__ = ["main"]`, Python's way of saying what Rust's private `fn` says. Write it
  at the end of the file: the pairs' line numbers are pinned. Spike 5 is spike 1 plus these four lines, and the five
  pass.
- **Not the way:** the other way to make the five pass is to give a project of scripts no doors at all. Its
  `pyproject.toml` declares no build system, so it is no library. Spike 3 does this: `mark_exports` keeps a module only
  where the project declares a build system or the module is an `__init__.py`. It takes away every route of fifteen
  plan programs (`plans/what-holds`, `plans/inside-a-step`, `pairs/ways`, …: one module and a manifest without
  `[build-system]`), as well as the sloppy pipeline's doors and the flat places' door. Do not take this way.
- **One law moves on purpose.** `pairs_pipeline.rs::python_clean_the_places_are_made_whole_at_the_entry` holds that
  every read of `sunspots.series.load` is whole by `sunspots.cli.run` alone. `load` is in the package's `__all__`, so
  under the fix its read is also whole by its users. This is the move #435 is for. Write the law as: whole by
  `cli.run`, and by the users of `load`.
