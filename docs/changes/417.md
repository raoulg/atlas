title: A field changed in place through &self is a change of self
area: engine
commit: pending
pictures: []

A Rust method that changes a field of `self` through `&self`, by a type that changes in place, now changes `self`, as
`&mut self` with `self.n += 1` does. The types are those Atlas already reads for a `static` and for a parameter:
`AtomicUsize`, `Arc<AtomicUsize>`, `Arc<Mutex<Vec<u8>>>`, `Cell`. `self.n.fetch_add(1, ..)`, `self.n.set(..)` and
`self.n.lock().unwrap().push(..)` are each a step that changes `self`, and the method's codomain holds its struct. Before,
each was a call Atlas could not follow and the method left nothing behind, so `atlas-code check` asked `nothing` of it.

The same count kept in a `static` the method raises still draws `Global(..)` changed, not the struct: Atlas tells the
two apart by where the change lands.

```text
example: engine/tests/pairs/interior/rust, Atomic.bump(&self) with self.n.fetch_add(..)
  before   bump                      changes nothing        check: nothing
  after    bump · changes Atomic     (as Plain.bump(&mut self) with self.n += 1)
```

On Atlas's own code the finding on `Cache.read_anew` (an `AtomicUsize` its clones share, raised through `&self`) goes.
