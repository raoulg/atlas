A socket's operations were drawn toward its place with a `?`: Atlas knew where a `recv`, a `read_to_string` on a
`TcpStream` or a Node `data` listener went, but not which way. Each operation now goes the way a file's does, in every
language: a receive is read from the place and stands on the left of its step, a send is written to it and stands on
the right. Connecting writes, as a file opened to read and write is drawn as written, and Node's `socket.end(data)` is
a write. So the client above sends its name from `main` and hears the greeting in `hear`, and the address stands
between them; the server's connection is read and written, in both.

Node's descriptors and file handles are doors as Python's file objects and Rust's `File` are: `fs.openSync(p, "w")`
and `fs.promises.open(p, "w")` open `p` the way their flags say, and `fs.readFileSync(fd)`, `fs.writeSync(fd, ..)`,
`handle.readFile()` and `handle.writeFile(..)` read and write that file, also where the descriptor or the handle is
handed to another function. An operation on a door goes to the opening that made it, so two files opened on one line
(`with open(a) as src, open(b, "w") as dst`) are two places.

Whether what a read gives is used is decided alike in more forms: `f.read_to_string(&mut s).unwrap()` makes `s` as
`f.read_to_string(&mut s)?` does, `let _ = f(x)` drops what `f(x);` drops, and a Node listener uses what its event
brings where its function's parameters go on.

analyze --no-cache, Atlas and every program under engine/tests/pairs, base against branch: the sockets pair's touches
of the network go their way in the three languages, and a lingering read whose bytes go nowhere is a check (Python's
`if not conn.recv(..)`, Node's `conn.on("data", () => {})`). Rust's handles pair reads `data.txt` into the text it
counts, so the read is used. In Atlas's own code `serve`'s reads and replies, the tests' connections and Studio's
`files.get` go their way; `exit_when_stdin_closes`, `Cache.sweep` and a test helper use what they read where it is
handed on under `let _ =`. The handles pair has a TypeScript side.
