Atlas Studio stopped at 99% opening a Python program with a TypeScript app beside it (`ruimtelijke-knowledge-graph`, whose
app reads `@tanstack` and `@vitest`): the reading took sixteen minutes, and the bar, measured against the last start, waits
at its end until the reading is done. Now it reads in 80 s, as before 0.71.0's readers' round, and the page draws its first
picture at once. The picture is the same: `atlas-code analyze --no-cache` writes the same bytes for that program, for Atlas
itself and for every TypeScript program under `engine/tests/pairs`, `engine/tests/plans` and the fixture.

A name a step changes in place holds a value of its own (#355). The TypeScript reader asked that of a name by walking the
whole body and reading every call in it, again for each name it followed at each call: in a long library function, at
every one of its calls, for each of the names a value stands for, eight bindings deep. What a body changes in place does
not depend on the call that asks, so it is now found once for the body, as the set of bindings its calls change, and each
name is looked up in it.

Bars: Reading rkg, cold, 0.71.0's round (bcf0d7f) = 958 s; Reading rkg, cold, after = 81 s; Reading rkg, cold, before #355 (985d073) = 78 s | `atlas-code view --no-cache --no-open --timings` of `ruimtelijke-knowledge-graph` at `8bc93f8` on a laptop (Apple M-series, one reading each, run one after the other); the `read` phase. Nearly all of the 958 s went to 36 bodies of `@tanstack` (`--timings` stages, `body`). What the 80 s still spend is #401.
