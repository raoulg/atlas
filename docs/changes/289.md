Working out what every function reads back and changes (`flow::of`) set both the time and the peak memory of a view
once the reading was kept: Studio's draw after its first start, and every `atlas-code view`. It now keeps what a body
does at its places once, shared by every caller that asks, under a key of numbers rather than of formatted text, and
works out each context of a function once for both what it reads back and what it changes. The page is the same, byte
for byte. Nothing in the picture changes; what does is how long it takes, measured on Atlas itself:

```text
atlas-code view . --no-open --timings FILE, warm, five alternating runs each, median (macOS arm64, load 27-35)

                 wall     user     flow::of   peak memory
before (0607e9f7)  5.92 s   4.41 s   5.59 s     561 MB
after              1.03 s   0.87 s   0.78 s     211 MB
```
