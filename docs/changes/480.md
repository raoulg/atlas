A loop over a tuple, list or set written in place is named by what it binds and how many members it holds, `for layer
in 4 layers`, where it was named by the whole literal's source; its members are the steps before it. A name that takes
no plural is counted in members (`for _ in 2 members`), a pattern by what it binds (`for (a, b) in 2 × (a, b)`), and a
short literal of constants keeps its members (`for split in ("train", "valid", "test")`). Rust's `for x in [a, b]` and
TypeScript's `for (const x of [a, b])` are named the same way.

A call through a table the module keeps, looked up by a value, `ACTIVATIONS[config.activation]()` with `ACTIVATIONS =
{"gelu": nn.GELU, ..}`, is a choice between the table's entries, as a `match` on the value with a case per key is: the
page draws a frame `one of · config.activation` with an arm per entry, each under its key, and the route reads `GELU()
· when config.activation is "gelu"`. It was one step that gave four values of no name. The table must be what the module
wrote: two entries or more, changed nowhere, its name not bound again where it is read, and a key that is no constant;
any other table lookup is drawn as before.
