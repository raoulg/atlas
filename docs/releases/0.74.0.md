Atlas 0.74.0 draws one program the same in Python, Rust and TypeScript in many more places: an input you may leave
out, a field, a method a family only declares, a decorator, a value a route gives back. The overview opens on the
shape of the program, in four columns with its libraries and places folded, and a route draws the chain its data takes,
with what only says how (the instance a step runs on, an error it hands on) said on the step. A program that reads
TypeScript libraries is read five times faster.

## Every route ends where its value lands

Kind: wrong

A route that gives back a number, a string, a list or an option drew a box that gave nothing: `loudest -> float` ended
at no place. It now ends at a box labelled by the type it gives back, as a route that gives back a type of the program
does. A record built from its fields (a dataclass, a struct) ends at the record it builds.

Compare: releases/0.74.0/img/ends-before.png = 0.72: `loudest` gives nothing; releases/0.74.0/img/ends-after.png = 0.74: `loudest` ends at `float`

## A focus shows what its box takes on the left and gives on the right

## An input you may leave out writes where its default says

Kind: wrong

`save_report("draft")` beside `save_report("final", Path("out/report.txt"))` writes one file, whether the default is
the parameter's, a fallback in the body (`path ?? …`, `path or …`) or an `Option` the function unwraps. A fallback is
completed by the callers, and an empty default (`process.env.RAW ?? ""`) keeps the root of the path it is joined into.

Diagram: releases/0.74.0/img/defaults.svg | Decided from principle (#428): an input the caller may leave out is its default wherever no caller hands it, and what the caller hands where one does. An illustration of the rule.

## An object reads and writes where it was set up

Kind: wrong

A field is what the constructor that built the value set it to: `Shelf::new(PathBuf::from("drafts")).index()` reads

## A method a family only declares draws nothing of its own

## A decorator is a mark on its function, and its errors are the function's

Kind: wrong

A decorator written as a call (`@strict(least=1)`, `@jaxtyped(typechecker=beartype)`) was drawn as a step of its module,
and one written as a name (`@guarded`) not at all. Both are now part of the definition: a mark `guarded` on the
function they stand above, and a call of that function hands on what the decorator may raise, `tidy guarded +1 error
type`. Wrapping a function by hand (`tidy = guarded(_tidy)`) is still a step.

Compare: releases/0.74.0/img/guards-before.png = 0.72: `tidy` drawn as if undecorated; releases/0.74.0/img/guards-after.png = 0.74: `tidy`, `scale.apply` and `mean` each marked `guarded`, with the error the check may raise

## TypeScript reads what its tsconfig compiles, and says what it left out

Kind: wrong

A TypeScript package is read as its compiler reads it: the files `tsconfig.json` names by `files` and `include`, less
`exclude` and `outDir`, along `extends` and `references`. A script beside `src/` that a `package.json` command runs is
that command's route. What was found and not read is said, with its folders:

## Smaller things that were drawn wrong

Kind: wrong

- `atlas changes` says what a changed step was wherever a route reaches it, also in one reading only (#385).
- `route`'s text numbers a choice inside an arm within that arm, as the page draws it (#393).
- A TypeScript library installed as a link in `node_modules` is read anew when its code changes (#441).
- An environment variable whose fallback is the same variable is that variable (#424).
- A type written in full, `torch.nn.Module`, is that type; its module `nn` is no longer drawn as a type of its own (#445).
- A Python package's exported function draws the places its users hand it, as Rust and TypeScript do (#435).

- A literal only a test hands is a place of the test's route, never of the command's; `check` no longer names a file nothing writes (#473).
- An overview where one package only writes, beside types that cross between packages, draws instead of stopping with a layout error (#471).
