Atlas 0.69 draws where a program keeps its files by what keeps them: a store, a cache, a folder of the
project's own is one box that opens into its files. And it names them by what the code says, not by
whatever a variable happens to be called.

## Where your files are, by what keeps them

A place on disk belongs to the type in your code that keeps it: the one whose value holds the folder
(`self.root`), whose constructor takes the path, or whose method goes to the disk there. Closed, the
type is one box, `Workbench`, `Cache`, `Repo`; a click opens it into the files it keeps, and those fold
into their folders as before. Files a program hands around as bare paths stand alone: nothing in that
code says they belong together. Below, Atlas drawn by itself: thirty boxes named after variables
(`{out}/.atlas/`, `{a}/.git`, `Disk(file)`) are now the handful of places Atlas's own code keeps,
the repository it reads, the libraries' environment, what it makes beside the repository, what it caches,
what it lays out for a moment and the user's settings.

Compare: releases/0.69.0/img/places-before.png = 0.68: Atlas drawn by itself; releases/0.69.0/img/places-after.png = 0.69

## A type's folder, as the code writes it

The same files, kept once through a type (`Workbench.of(project).file("report.txt")`) and once through
bare paths (`made_dir(project).join("report.txt")`), are the same places in Python, Rust and TypeScript:
a path a type's method builds keeps its name. Only the first draws them as one `Workbench`.

Compare: changes/244-groups-before.png = 0.68: three files; changes/244-groups-after.png = 0.69: the Workbench that keeps them

Issues: #246

## Names that say where

A name a function gives a value is that function's, as its parameters are: two functions that each
write a `file` write two files, not one `Disk(file)`. A message said when a value is missing
(`expect("has a parent")`) never names a place.

Compare: changes/245-before.png = 0.68: one Disk(file) for two files; changes/245-after.jpg = 0.69: one place for each

Issues: #245, #248

## Atlas Studio

The terminal docks at the bottom, on the left or on the right, and stays where you put it. Settings name
the commit of the build that runs, so you can tell builds apart. And the history follows git: a commit,
a push or a fetch shows without a reload.

Pictures: changes/242-docks.png, changes/249-after.jpg

## Faster checks

Atlas's checks of Studio no longer build Atlas on three platforms only to have a file there: a Studio
check takes minutes where it took a quarter of an hour.

Bars: Studio's check before = 24.6 min; Studio's check now = 3.9 min | Studio's check on Linux, from a run on `next` before the change and the first after it.
