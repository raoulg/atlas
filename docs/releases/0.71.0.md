Atlas 0.71.0 draws more of your code as it really runs: the files a loop writes, a folder copied to any depth, a file
or a connection handed from function to function, a path an environment variable names. Forms that say the same
thing now draw the same picture in all three languages. And the page opens on the one picture the agent reads.

## A loop writes only the files it writes

Kind: wrong

For each `kind` of `["books", "games"]`, `root / kind / f"{kind}.csv"` was drawn as four files, two of which no run
writes. A name bound once is now one value wherever it stands. Two lists kept in step only by an index are still two
values, and Atlas draws every pairing: the code does not say they belong together.

Diagram: releases/0.71.0/img/variable.svg | Decided from principle (#324): one name, bound once, is one value.

Shots: changes/324-before.jpg = 0.70: four files, two in the other kind's folder; changes/324-after.jpg = 0.71: the two files the route writes

Issues: #324

## A recursive copy reaches every depth

Kind: wrong

A function that calls itself on each subfolder was followed one level at a time, down to a limit, and ended in a
folder of a `{source}` no call hands. Now the recursion is followed to where it ends: the copy reads `data/**` and writes
`backup/**`, as a walk with `rglob("*")` does. Two functions that call each other in turn are one recursion too.

Diagram: releases/0.71.0/img/fixpoint.svg | Decided from principle (#325): a call that goes one folder deeper each time completes to one place at every depth.

Shots: changes/325-before.jpg = 0.70: a place per level of `data/`, and a `{source}` no call hands; changes/325-after.jpg = 0.71: the copy reads at any depth in `data/` and writes at any depth in `backup/`

Issues: #325, #345

## A file or a connection you hand on keeps its place

Kind: wrong

A function handed an open file read and wrote nothing, so `atlas-code check` asked why `emit` does nothing, and a
server's connections reached a bare `Web`. Now every read, write and send through a handle goes to the place it was
opened at, also in the functions it is handed to: what comes in on the left, what goes out on the right.

Diagram: releases/0.71.0/img/doors.svg | Decided from principle (#323): an operation through a door is a line to the place the door was opened at.

Shots: changes/323-handles-before.jpg = 0.70: `count` and `emit` touch no file; changes/323-handles-after.jpg = 0.71: `count` reads `File(data.txt)` and `emit` writes `File(report.txt)`; changes/302-after.png = 0.71: the greeter's route ends at `Web(127.0.0.1:7878)`, where its client arrives too

Issues: #302, #323, #353

## A file and the folder that holds it are found the same way

## Smaller things that were drawn wrong

Kind: wrong

- A TypeScript or Rust client that looks its URL up in a table it writes (`PATHS[env]`) met no route; now it meets them, as in Python (#236, #304).
- A local such as `loud = samples.abs() > 0` is the function's own value, no longer a value from beyond (#318, #319).
- A list changed in place (`both.push(x)`, `rows[0].push(x)`) is a new value of the list from there on (#355, #366, #374).
- Two versions of one library are two libraries: on Atlas itself, `atlas-code changes` of a commit against itself said 505 routes changed, now none (#372).
- The overview of packages is built as a route is, so opening a package only refines it, and never adds a line the closed box lacked (#69).

## Eighteen ways of writing one thing, drawn alike

Kind: alike

Each row is one thing written in several ways, and every form in it now draws what the right says. Before, at least
one of them drew something else: an extra step, a literal for a name, or nothing at all.

- `os.listdir(d)` ≡ `fs::read_dir(d)` ≡ `p.read_dir()` ≡ `readdirSync(d)` → the folder's entries, `d/*` (#236, #327)
- `os.path.join(d, f)` ≡ `Path(d) / f` ≡ `d + "/" + f` → one path (#236)
- `PATHS[env]` ≡ `paths.get(key)` of a `HashMap::from([..])` ≡ an object literal's key → one of the paths the table holds (#236)
- a function that calls itself on each subfolder ≡ `rglob("*")` → `d/**`, every depth (#325)
- `p.push(x)` ≡ `p = p.join(x)`, and `p.pop()` ≡ `p = p.parent()` → the path, bound anew (#327)
- `tokio::fs` ≡ `async_std::fs` ≡ `std::fs` → disk (#327)
- `OpenOptions::new()` ≡ `File::options()`, and `open(p, "a")` ≡ `appendFileSync(p)` ≡ `.append(true).open(p)` → the file `p` (#300, #301)
- `os.environ.get("R", "")` ≡ `env::var("R").unwrap_or_default()` ≡ `process.env.R ?? ""` → the file `$R` names (#248)
- `shutil.rmtree(p.parent)` ≡ `remove_dir_all(p.parent())` ≡ `rmSync(dirname(p))` → the folder `p` is in (#248)
- `note.relative_to(root)` ≡ `note.strip_prefix(root)` ≡ `path.relative(root, note)` → a key a join at `root` undoes (#352)
- `std::path::absolute(p)` ≡ `path_clean::clean(p)` ≡ `p` → the place it was handed (#250)
- `("127.0.0.1", 7878)` ≡ `SocketAddr::from(([127, 0, 0, 1], 7878))` ≡ `createConnection(7878, "127.0.0.1")` → `127.0.0.1:7878` (#323)
- `levels.get(name)?` ≡ `&levels[name]`, and `first()?` ≡ `at(0)` ≡ `next(iter(..))` ≡ `[0]` → a lookup, no step of its own (#346)
- `let gap = a.db - B.db; draw(gap)` ≡ `draw(a.db - B.db)` → a name adds no arrow (#328, #343)
- `println!("{}", Plain.name())` ≡ `Plain.name()` → a `Plain()` step builds the value first (#299, #303)
- `both: list[Level] = ..` ≡ `let both: Vec<Level> = ..` ≡ `const both: Level[] = ..` → an annotation, no read (#356)
- `for (const k in KINDS)` ≡ `for k in KINDS` → the keys the table writes (#327)
- `sqlite3.connect(os.path.join("data", kind, "counts.db"))` ≡ Rust's `Connection::open(..)` → `data/{kind}/counts.db` (#327)

Diagram: releases/0.71.0/img/names.svg | Decided from principle (#328): written in place or named first, the code draws one picture, since a name adds no arrow.

Issues: #236, #248, #250, #299, #300, #301, #303, #323, #325, #327, #328, #343, #346, #352, #356

## The page opens on the picture the agent reads

Kind: ui

`atlas-code serve` read a program twice: first without its libraries, a picture that was no zoom or filter of the
complete one, then again with them. Now it reads once, and the page opens on the complete picture, the one the agent
reads. A file no reader asks about (an image, a note, a log) no longer makes it read again.

Bars: first picture, 0.70 = 14.1 s; first picture, 0.71 = 22.5 s; complete picture, 0.70 = 38.9 s; complete picture, 0.71 = 22.5 s | Atlas itself, cold start. 0.70's first picture was quicker but incomplete; the complete one comes 16 s sooner.

Diagram: releases/0.71.0/img/one-reading.svg | One reading, drawn for both sides.

Issues: #228, #290, #360

## The loading bar no longer stands at 99 %

Kind: ui

A bar shows only when a start really reads code, and is timed by the last starts that did. The time expected fills four
fifths of the bar; a reading that takes longer moves through the last fifth in seconds, so the bar never stalls at 99 %.

Compare: changes/415-bar.png = 0.71: the last fifth of the bar is the time beyond the estimate
