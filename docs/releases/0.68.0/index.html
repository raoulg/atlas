Release 0.68.0

What changed in Atlas 0.68.0

Atlas 0.68 brings Atlas Studio, a desktop app around the engine and viewer, and a working-tree index that makes a repository open quickly the second time. Most of the rest is about faithfulness: after the laws review of 20 October, routes, zoom and atlas check were held to the mathematics they claim, and many places where the picture differed from the code were fixed in the Python, Rust and TypeScript readers. The tests now check laws, and a sampler checks the same laws on real programs.

Atlas Studio, a desktop app

Atlas Studio is a native window (Tauri) that runs its own atlas serve for each open workspace and shows the Atlas view with the history in the sidebar. Around the picture it has a file tree that lists files the way Atlas reads them and marks the files the graph defines something in. Clicking such a file opens it in the picture (a notebook or script on its route), and any other file opens in a preview for source, Markdown, HTML and PDF. It also has a terminal running the user's own shell, a workspaces page (⌘O, File › Open Recent) and one top bar that holds the view's controls. Lessons are ordinary .md or .html files that embed saved Atlas views at a readable scale and run a Python script whose output and figures appear beside the text. Every release and nightly comes with a macOS disk image for Apple silicon and Intel and a setup program for Windows, installed by install-studio.sh and install-studio.ps1. Studio's server and shells end when Studio ends, also when it is killed.

Opening a repository: an index on disk, a picture sooner, no network

Atlas keeps what it read of a working tree in .atlas/index/ (one folder per worktree and Atlas build) and reads again only the parts whose files, manifest or environment changed. A warm read gives the same graph as a cold one, and --no-cache skips the index. atlas view, atlas check, atlas serve and atlas mcp share it. An open atlas serve page redraws from a fresh snapshot after an edit and keeps its route, filters and open boxes. In a measurement on the Atlas repository itself (debug build, atlas analyze --libraries 0), a warm read took 0.14 s against 18.9 s without the index. While serve reads libraries, the page first shows a marked picture of the repository's own code, then the complete one. The loading bars only rise and keep pace with how long each phase took at the last few starts. The viewer carries D3, ELK and highlight.js in itself, so a page renders without a network connection.

Zoom keeps its laws, and the tests check them

The laws review of 20 October found pictures that broke the rules in docs/reference/mathematics.md, and 0.68 fixes them. Opening a family no longer splits a step outside it. A folded directory stands on the side its files are on instead of between the steps. A helper called by two steps writes each caller's file under that caller, not both. A route's parameters keep their names (Circle · c, Square · q instead of one Shape), and the dotted "calls, no data" line is no longer hidden when data also joins two packages. The viewer's model is now viewer/plan.js, and every route of every test program is checked, for every set of open boxes, against an oracle and the quotient. A step beyond the plan's budget is the image of its whole body. The engine's tests now check laws (fibers commute, quotients compose, a saturated fiber commutes with its quotient) on graphs that proptest draws, and check facts in the graph instead of Atlas's wording or line numbers. A sampler checks the same laws on real programs at reproducible sites. It found two faults that are fixed in this release (#213, #214).

Values: what a call hands, changes and lends

A call now hands each value to the parameter its argument fills, by position, name or keyword, and no longer by type and count. The plan also follows a value through self, a closure, an index or the inner call of a chain. Values a body binds without a call (a loop variable, a let from an if, a table lookup) are made by that body instead of coming from beyond, and a value the body uses itself, or a result its caller drops, is drawn as such. A call that changes a value hands back the caller's value at a new moment, under the caller's name. Figures are values: two plt.subplots() in one body are two figures, one figure drawn on by several steps is one, and a figure lent through a field or between two parts of one value is followed to where it is drawn.

Errors, choices and classes as the code writes them

An error is a value: the step that raises it hands it to its callers, up to the route, instead of ending it at its own border. A call into a family can fail with any error its overrides can raise. Before, it kept one of them, chosen by hash order, so two readings of the same code could differ. Choices follow the code's forms: the code after an early return is the other arm, the left side of x ?? y, x && y and Python's or/and always runs, and a name an arm binds is made by that arm. Calls through classes run what the language runs: methods by the method resolution order, super() and calls through a class. Building a class runs its initializer along the class's order, with the initializer's effects in call order, and does not open into the class's methods. An override in a dispatch runs on the dispatch's receiver. A Rust method called by its path runs on its first argument, and a TypeScript this call runs on the route's class.

Places and parts as the repository has them

Places stand where the code puts them. A place written and only read back to check stays in the codomain, a place read and written stands on both sides, an HTTP method decides which way a request goes (a DELETE is no longer drawn as a read, a urlopen without data is a GET), and an environment variable with a default is one place. A path whose root is unknown keeps its hole instead of falling back to its last literal. A repository of Python scripts with only a requirements.txt (or setup.py, setup.cfg, Pipfile) is now a part with entry points. Two parts with one package name no longer share ids, each part has its own Makefile, and a TypeScript part is named by its package.json.

atlas check, the history and prophecies say what they claim

The rules flagged in the laws review now check what their names claim. Here are the main cases.

  • sums treats a union written in place as a sum.
  • overrides walks the C3 order of the bases and compares TypeScript structurally.
  • doors checks every overload.
  • places asks the function that fixes a path.
  • changes follows values, not parameter names.
  • gives now fires in TypeScript.
  • choices reads across bodies.
  • nothing separates what Atlas cannot see from dead code.
  • layers uses the viewer's quotient.
  • lens focuses on a table or a named file.
  • prophecy resolves crate::.

atlas check --json prints one document for several parts. The history marks only the step that changed, also when a step is inserted into a chain. prophetize writes Python markers that import cleanly and can mark .js files.

Also still open are the package overview, which is still built outside the plan (#69), the value of a Rust unit struct (#207, an ignored test), and the review of the engine's tests (#204).
