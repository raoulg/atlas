Atlas 0.73.0 draws one program the same in Python, Rust and TypeScript in many more places: an input you may leave
out, a field, a name a function binds, a test, a method a family only declares. Every view, from the overview to one
command's route, is drawn from one plan by one rule, so opening a box never moves another. A program that reads
TypeScript libraries is read five times faster.

## Every command at once shows what each one takes and gives, and where they meet

Kind: wrong

The view of all routes of a kind drew each route from its function's own signature: a command started from nothing,
and a file a function was handed was drawn by its format, `File(*.csv)`, beside the file another function wrote. Now
each route is its own picture closed. It starts from the command line it is run from (`sunspots · 6`, one box), gives
what its picture gives, and a file a caller names is drawn by what names it: `download` writes and `load` reads one
`File(data/raw/sunspots.csv)`.

Compare: releases/0.73.0/img/437-before.png = 0.72: no command, and the download and the read are two places; releases/0.73.0/img/437-after.png = 0.73: the command starts every route, and `download` and `load` meet in one file

Issues: #437, #434, #449

## Every route ends where its value lands

Kind: wrong

A route that gives back a number, a string, a list or an option drew a box that gave nothing: `loudest -> float` ended
at no place. It now ends at a box labelled by the type it gives back, as a route that gives back a type of the program
does. A record built from its fields (a dataclass, a struct) ends at the record it builds.

Compare: releases/0.73.0/img/439-before.png = 0.72: `outages` and `summary` give nothing; releases/0.73.0/img/439-after.png = 0.73: `outages` ends at `string[]`, `summary` at `string`

Issues: #439

## A call at the edge of a large route shows what its whole body does

Kind: wrong

A large route is drawn to a depth, and each call beyond it stands for its body. That stand-in now takes and gives what
the body does when opened: `news.read.headlines` builds its `Feed` inside the route, where it was drawn taking a
`Cached` from outside, as if another object were read.

Diagram: releases/0.73.0/img/cut.svg | Decided from principle (#438): a step drawn at the cut is its whole body opened and closed again. An illustration on the `diamond` pair.

Issues: #438

## A focus draws a package as the overview does

Kind: wrong

Shift-clicking a package drew it with a border of its own: a package that takes and makes tensors of four ranks
showed one type coming in and nothing going out. A focus is now the part of the overview that touches the package, so
the package has the border the overview gives it, and a type stands where the overview puts it, in every focus.

Compare: releases/0.73.0/img/399-before.png = 0.72: one type from the rest of the code, nothing out; releases/0.73.0/img/399-after.png = 0.73: the tensors the package takes and gives, in the frame of `torch` as in the overview

Issues: #399

## A folder's listing reads what is written inside it

Kind: wrong

A route that writes `data/raw/{kind}/download.json` and a route that lists `data/raw/` drew two places with nothing

Compare: changes/381-before.png = 0.72: three places, no line between the writes and the listing; changes/381-after.png = 0.73: one box the package writes and reads

## An input you may leave out writes where its default says

Kind: wrong

`save_report("draft")` beside `save_report("final", Path("out/report.txt"))` writes one file, whether the default is
the parameter's, a fallback in the body (`path ?? …`, `path or …`) or an `Option` the function unwraps. A fallback is
completed by the callers, and an empty default (`process.env.RAW ?? ""`) keeps the root of the path it is joined into.

Diagram: releases/0.73.0/img/defaults.svg | Decided from principle (#428): an input the caller may leave out is its default wherever no caller hands it, and what the caller hands where one does. An illustration of the rule.

Issues: #428, #383, #350, #427

## An object reads and writes where it was set up

Kind: wrong

A field is what the constructor that built the value set it to: `Shelf::new(PathBuf::from("drafts")).index()` reads
`drafts/index.txt` alone, not the index of a shelf another function builds. A step reads where its own object was set
up, not every object of its class, and a call in a loop is handed what the round before made. A variant's field is
carried through the `match` that takes it apart.

Diagram: releases/0.73.0/img/setup.svg | Decided from principle (#395, #368): a field is what the constructor that built the value set, and a step reads where its own object was set up. An illustration on the shelves of the `order` pair.

Issues: #395, #407, #349, #368, #354

## A method a family only declares draws nothing of its own

Kind: wrong

An `@abstractmethod`, a `Protocol`'s method, a trait method without a body, or a TypeScript `abstract` or `interface`
method runs no code, yet the overview drew its signature as if it did: `BaseAggregator` took a 3D tensor and gave a 2D
one. Now such a method takes and gives nothing, and a call of it draws the members that fill it in.

Diagram: releases/0.73.0/img/declared.svg | Decided from principle (#430): a method with no body has no arrow of its own, and a call of it runs one of its members. An illustration on the `abstract` pair.

Issues: #430

## Smaller things that were drawn wrong

Kind: wrong

- `atlas changes` says what a changed step was wherever a route reaches it, also in one reading only (#385).
- `route`'s text numbers a choice inside an arm within that arm, as the page draws it (#393).
- A TypeScript library installed as a link in `node_modules` is read anew when its code changes (#441).
- An environment variable whose fallback is the same variable is that variable (#424).
- A type written in full, `torch.nn.Module`, is that type; its module `nn` is no longer drawn as a type of its own (#445).
- A Python package's exported function draws the places its users hand it, as Rust and TypeScript do (#435).

Issues: #385, #393, #441, #424, #445, #435

## Twelve forms in three languages, now one picture each

Kind: alike

A form written differently in Python, Rust and TypeScript, but saying the same thing, is now read as one construct and
drawn as one picture: a test, a value nobody reads, a local named like a module's function, a method changing its
struct through a counter, a tuple bound at once, two versions of one library, a package meant to be imported.

Diagram: releases/0.73.0/img/isomorphic.svg | Decided from principle: forms that say the same thing are one construct, and one construct draws one picture, in every language. Applied this release to twelve forms, each in its issue.

Issues: #363, #375, #394, #436, #417, #376, #380, #403, #404, #347, #240, #377, #378

## The types of a library stand in its frame

Kind: ui

The overview drew a library's types loose among the program's own classes: vectormesh's eleven tensor rank families
stood beside its components. A library's types now stand in a frame of that library, `▾ torch`, open at the rank
families; clicking its title closes it to one box, `torch · N types`, N the types it holds.

Compare: releases/0.73.0/img/431-before.png = 0.72: the rank families stand loose among vectormesh's own classes; releases/0.73.0/img/431-after.png = 0.73: one `▾ torch` frame holds the rank families, `nn.Module` and `Optimizer`

Issues: #431

## A program with TypeScript libraries reads five times faster

Kind: speed

A Python program with a TypeScript app beside it that uses `@tanstack` and `@vitest` read cold in 89 s; it now reads
in 16 s. What a TypeScript name holds is found once and shared by every place that names it, where it was unfolded
anew at every call. The picture is byte for byte the same.

Bars: Python + TypeScript program, cold, 0.72 = 89 s; Python + TypeScript program, cold, 0.73 = 16 s | `atlas-code analyze --no-cache`, release builds, on a developer machine; the output is the same bytes for that program, for Atlas and for the 460 programs under `engine/tests`.

Issues: #401

## A Python program reads a third faster

Kind: speed

A cold read of a Python program spent most of its time asking where each name stands in its file. A body's
structure is now read once while the body is read, as the Rust reader does. Nothing Atlas draws changes.

Bars: goad_toolkit cold, before = 0.601 s; goad_toolkit cold, after = 0.295 s; vectormesh cold, before = 0.766 s; vectormesh cold, after = 0.384 s | `atlas-code --no-cache view --no-open --timings` at `--libraries 1`, an empty cache and no index, release builds before and after the change, seven interleaved rounds on a developer machine, the median of each.

Issues: #410
