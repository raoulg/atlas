Atlas 0.73.0 draws one program the same in Python, Rust and TypeScript in many more places: an input you may leave
out, a field, a name a function binds, a test, a method a family only declares. Every view, from the overview to one
command's route, is drawn from one plan by one rule, so opening a box never moves another. A program that reads
TypeScript libraries is read five times faster.

## Every command at once shows what each one takes and gives

Kind: wrong

The view of all routes of a kind drew each route from what its function's own signature said: a command started from
nothing, and the figure a class route draws was left out. Now each route is its own picture closed: it starts from the
command line it is run from (`sunspots · 6`, the six exports of the sunspots pipeline, one box), and gives what its
picture gives, `sunspots.Plot` its `Plot`, the `Figure` and the `*.png` it saves.

Compare: changes/437-kind-before.png = 0.72: the routes start from their files alone, and `Plot` gives no `Figure`; changes/437-kind-after.png = 0.73: every route starts from `sunspots · 6`, and `sunspots.Plot` gives `Plot`, `Figure` and `File(*.png)`

Issues: #437, #434

## An input you may leave out writes where its default says

Kind: wrong

`save_report("draft")` beside `save_report("final", Path("out/report.txt"))` writes one file, whether the default is
the parameter's, a fallback in the body (`path ?? …`, `path or …`) or an `Option` the function unwraps. A fallback is
completed by the callers, and an empty default (`process.env.RAW ?? ""`) keeps the root of the path it is joined into.

Diagram: releases/0.73.0/img/defaults.svg | Decided from principle (#428): an input the caller may leave out is its default wherever no caller hands it, and what the caller hands where one does. An illustration of the rule.

Issues: #428, #383, #350, #427

## An object reads and writes where it was set up

Kind: wrong

A field is what the constructor that built the value set it to: `Shelf::new(PathBuf::from("drafts")).index()` reads
`drafts/index.txt` alone, not the index of a shelf another function builds. A step reads where its own object was set
up, not every object of its class, and a call in a loop is handed what the round before made. A variant's field is
carried through the `match` that takes it apart.

Diagram: releases/0.73.0/img/setup.svg | Decided from principle (#395, #368): a field is what the constructor that built the value set, and a step reads where its own object was set up. An illustration on the shelves of the `order` pair.

Issues: #395, #407, #349, #368, #354

## Twelve ways of writing one thing, drawn alike

Kind: alike

Each row is one thing written in several ways, in Python, Rust and TypeScript. Every form in it now draws what the
right says; before, at least one of them drew something else.

- `f(x)` ≡ `_ = f(x)` ≡ `void f(x)` ≡ `let _ = f(x)` → what was handed to `f` is used (#363)
- `if not conn.recv(1024): break` ≡ `match conn.read(..) { Ok(0) | Err(_) => break, Ok(_) => {} }` → a check of the read, not a use (#363)
- `size = len(xs)` ≡ `const size = xs.length` ≡ `let size = xs.len()` → the body's own value, never the module's function `size` (#375)
- `rows[0].append(x)` ≡ `rows[0]!.push(x)` ≡ `rows[0].push(x)` → the next step is handed the rows with their type (#394)
- `Html(text).write(out)` ≡ `new Html(text).write(out)` ≡ Rust's tuple struct `Html(text).write(out)` → a call of `Html.write` (#436)
- `&mut self` with `self.n += 1` ≡ `&self` with `self.n.fetch_add(1, ..)` → the method changes its struct (#417)
- `let kept = Some(level)` ≡ `let mut kept = None; kept = Some(level)` → `draw` is handed `level` (#376)
- `let (a, b) = (x, y)` ≡ `let a = x; let b = y` → each name its own value (#380)
- a pytest `test_*` ≡ a Cargo `#[test]` ≡ an `it("…")` callback → a route of its own, named by its test (#403)
- a Python project's `tests/` ≡ a crate's `tests/` ≡ a TypeScript package's `test/` → read, and left out of the overview until asked (#404)
- a Python package with a build system ≡ a Cargo lib target ≡ a public `package.json` → asked what a user may import (#347)
- two versions of one library in a uv, Cargo or npm workspace → two libraries, each part reading its own (#240, #377, #378)

Issues: #363, #375, #394, #436, #417, #376, #380, #403, #404, #347, #240, #377, #378

## A program with TypeScript libraries reads five times faster

Kind: speed

A Python program with a TypeScript app beside it that uses `@tanstack` and `@vitest` read cold in 89 s; it now reads
in 16 s. What a TypeScript name holds is found once and shared by every place that names it, where it was unfolded
anew at every call. The picture is byte for byte the same.

Bars: Python + TypeScript program, cold, 0.72 = 89 s; Python + TypeScript program, cold, 0.73 = 16 s | `atlas-code analyze --no-cache`, release builds, on a developer machine; the output is the same bytes for that program, for Atlas and for the 460 programs under `engine/tests`.

Issues: #401

## A Python program reads a third faster

Kind: speed

A cold read of a Python program spent most of its time asking where each name stands in its file. A body's
structure is now read once while the body is read, as the Rust reader does. Nothing Atlas draws changes.

Bars: goad_toolkit cold, before = 0.601 s; goad_toolkit cold, after = 0.295 s; vectormesh cold, before = 0.766 s; vectormesh cold, after = 0.384 s | `atlas-code --no-cache view --no-open --timings` at `--libraries 1`, an empty cache and no index, release builds before and after the change, seven interleaved rounds on a developer machine, the median of each.

Issues: #410
