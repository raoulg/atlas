Atlas 0.72.0 draws a PyTorch model the way you write it: each submodule you call is a step, and each value between
two steps keeps its jaxtyping shape, from the inputs to the logits. The overview draws what every function gives back,
and leaves your tests out. A path built by helper functions is drawn whole.

## A PyTorch model draws its forward pass as a chain of shapes

Kind: wrong

A model that calls its submodules, `self.projection(x)` and `model(x)`, drew its forward pass as one dashed step to
values without a shape. Now calling a module runs its `forward`, and every value between two steps keeps the shape
its jaxtyping annotation declares. Printing or saving a model hands it on as a value and runs nothing.

Diagram: releases/0.72.0/img/forward.svg | Decided from principle (#422, #423): calling a module is calling its forward, and handing it on is not. An illustration of the rule: what Atlas draws of the course model is folded below.

Shots: releases/0.72.0/img/forward-0.71.png = 0.71: `model(dino, resnet)` is one dashed step to `logits`, and no value has a shape; releases/0.72.0/img/forward-0.72.png = 0.72: batch 384 and batch 512 through `Projection.forward` to batch 128 each, joined, then batch 256 through `NeuralNet.forward` to batch 47 (the chain wraps at `Concatenate2D.forward`)

Issues: #422, #423

## The overview draws what each function gives back

Kind: wrong

The packages view drew a type only where the code both made and took it. A function whose result no other function
took, such as `card(shelf) -> Card`, or a model's `forward` that returns `Float[Tensor, "*lead {self.out_size}"]`, drew
what it took and no line to what it gave back. Now every type a function makes or takes is a box of the overview,
in the smallest package that holds all its makers and takers.

Diagram: releases/0.72.0/img/overview.svg | Decided from principle (#419): every type a function makes or takes is a box, in the smallest package that holds all its makers and takers. An illustration on the shelf example: what Atlas draws of it is folded below.

Shots: releases/0.72.0/img/419-before.png = 0.71: `card` takes the shelf and gives nothing; releases/0.72.0/img/419-after.png = 0.72: `card` gives a `Card`

Issues: #419

## A path built through helpers is the whole path

Kind: wrong

A path that each folder of it names with a helper function of its own was followed only so deep, so the archive's
stand-up notes were written to `{monthDir.folder}/11/2/meetings/standup.md`, the folder three helpers down left as a
hole. Now each function's return is read once, as a term of its parameters, and the notes are written to
`~/archive/2026/11/2/meetings/standup.md`, in Python, Rust and TypeScript alike. Reading Atlas itself got slightly
faster for it (9.8 s to 9.2 s, cold).

Compare: releases/0.72.0/img/396-before.png = 0.71: a folder left as a hole, `{monthDir.folder}`; releases/0.72.0/img/396-after.png = 0.72: the whole path, `~/archive/2026/11/2/meetings/standup.md`

Issues: #396

## Smaller things that were drawn wrong

Kind: wrong

- A tensor written `Float[Tensor, "..."]`, which promises no axis, reads `Float Tensor · any rank`, where it was drawn raw (#420).
- A group of the places one type holds says how many it stands for (`EarlyStopping · 3`) and opens to its files; opening one stopped the page (#421).

Issues: #420, #421

## The overview shows your program, not its tests

Kind: ui

The overview drew all the code, tests included: a test's fixture file and the test's own types stood beside the
files the program reads. It now draws the program alone, without Rust's `#[test]` and `tests/`, pytest's `test_*.py`
and `conftest.py`, or a `*.test.ts`. The chip `without test code ✕` above the picture says so, and one click on it
draws the tests again.

Compare: releases/0.72.0/img/400-before.png = 0.71: the pytest file `test_disk` and the fixture only it reads; releases/0.72.0/img/400-after.png = 0.72: `without test code ×`, and `store` reads `shelf.csv` alone

Issues: #400

## A large Rust program is read an eighth faster

Kind: speed

A cold read of a 60,000-line Rust program takes 14.5 s, where it took 16.5 s, and a served page draws it as much
sooner: each function's return is read once, as a term of its parameters (#396). Python and TypeScript programs read as
fast as before, within the noise, with the same memory. Atlas's own test suite runs 8 % longer.

Bench: releases/0.72.0/bench.json | Each pair: `d52a057` (0.71.0) and `799090b` (0.72.0) built and measured interleaved on one runner, the median of 2 or 5 rounds each ([the run](https://github.com/raoulg/atlas/actions/runs/42122220401)). Over the releases: each release's night since the series began, on its night's runner (`docs/reference/performance.md`).
